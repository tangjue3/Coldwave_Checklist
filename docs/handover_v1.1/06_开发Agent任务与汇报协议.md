# 《寒潮清单》开发 Agent 工作协议（交接指令 v1.1）

> 总策划与素材统筹由 ChatGPT（本对话）负责；实际编写代码、导入素材、运行项目的 Agent 负责实现与报告。用户负责将消息/资料跨 Agent 传递，除非后续共享可访问仓库或工作区。

## 当前唯一允许的工程任务：INIT-001

**目标**：建立可启动、可复现的 Godot 4.7.2 稳定工程，不提前实现尚未锁定的剧情和素材。

完成这些具体事项：

1. 建立独立 Git 仓库、`.gitignore`、README 和规范目录（可参考 v1.0 的 `03_技术架构开发路线与验收.md`）。
2. 设置 Godot 2D 项目：基准 960×540，整数倍缩放、nearest 纹理过滤，默认中文字体可读；使用原生 GDScript。
3. 创建入口/标题菜单/空的超市/空的安全屋场景，并确保场景切换正常；只用明确标记的占位素材。
4. 建好 `GameState`、`SaveManager` 等**空接口和数据契约草案**，但不提前写正式道具/剧情结算；正式 schema 需等待 v1.1 再确认。
5. 测试：一键打开 Godot 项目；能够运行入口场景，进入两个空场景返回；无报错。
6. 记录 Godot 实际补丁版本、工程根路径、Git 状态、启动截图、可复现运行说明和任何阻断事项。

**停止条件**：项目初始化验收完成后停止；不要自行开始开发 D-7 到 D+7 的商店逻辑、建造数值、NPC 台词、动画片段或第二季。

## 审核原则

- **完整性优先**：核心操作真的在游戏中发生了，才算实现。
- **反馈有证据**：不要只写“已完成”，必须有文件、运行验证、截图和测试。
- **状态可追溯**：玩家资产、剧情 flags、时间结算与存档不能靠视觉假象掩饰。
- **美术单向交接**：我这边交付的概念图需转成工程资源后由 Agent 试用；有问题回报具体 asset ID、画面和期望修正，而不是直接丢掉风格。
- **需求分层**：第一季完成并通过验收之前，第二季暂停；不要因为未来设想把 MVP 拖成庞大工程。
