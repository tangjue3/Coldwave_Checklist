# 《寒潮清单》第一季 v1.1 剧情与美术补充包

> 2026-11-08；**仅补充策划、美术方向和任务分配，不包含已完成的游戏代码**。

## 如何使用

1. 开发 Agent 已拿到 v1.0 交接包：现阶段**只初始化工程**，不开始 D-7～D+7 的剧情和正式素材生产。
2. 初始化完成后，再加载本 v1.1 包；**v1.0 的 00–03 四份文件继续有效**。
3. v1.1 扩写以 `原事件ID + 后缀B/C` 的方式插入，**不推翻 v1.0 的 P00、P01..P07、D00..D07 和已定义的主角、人物旗标**。
4. 若出现冲突，以本文件的“补丁优先级”和新剧情文档为准，开发 Agent 必须列出差异后再改代码，不默默删去既有内容。
5. 参考美术概念仅用于确定视觉规范；不能直接把气氛图裁剪成正式可商用 spritesheet。

## 本轮解决的问题

| v1.0 问题 | v1.1 补强 |
|---|---|
| 剧情每天仅一次事件，像提纲 | 每天新增约一场“可玩戏”，形成 30+ 段主线/插入场景，含对白、条件、操作和回报 |
| 囤货后缺少剧情起伏 | 加入物流超时、旧楼电路、临期涨价、群聊舆论、灾后门锁危机、屋外互助、极寒最后一夜 |
| 反派只有坏，没有动机 | 明确孟雨薇的自利与恐惧；拒绝、交易、帮助都有独立反馈，不强迫接受坏人 |
| 好人仅用于送奖励 | 陈叔的技术帮助、唐宁交易渠道、韩启程转变形成可回收的前后呼应 |
| 美术还停留在单张参考图 | 提供可生产的资产台账、分辨率、动画、样式标准和验收方法 |
| 一次性生成全部资源风险大 | 按 P0 必须 / P1 第一季 / P2 后续 排批，先锁角色和场景比例，再做精灵与动画 |

## 类型题材调研（只借鉴叙事结构，不搬台词/IP）

- 2026-11-04 的 AI 短剧周榜报道中，重生极寒囤货作品《重生暴雪前舍了瓦房换铁堡》居高位，报道强调“提前布局、坚固住所、家庭/群像互助”的戏剧要素： https://lmtw.com/mzw/content/detail/id/259695/keyword_id/-1
- 2026 年爱奇艺已有《重生囤货，极寒末世躺赢》，故事包含重生、改造恒温堡垒、邻里冲突、长期生存，说明主线题材不稀缺： https://www.iqiyi.com/a_1h3kdtjlkph.html
- DataEye 对 2026 年 AI 剧漫剧的研究提到强情绪、重生、逆袭、末世的高频组合，也指出头部集中、同质化风险： https://www.jiemian.com/article/15210914.html

**我们的原创落点**：故事依旧直白爽快，但每个大冲突都让玩家靠已经购物/建好的物品获得实际回报；建筑横版剖面与物资陈列是镜头核心，不复刻别人的石堡、金山、具体人物、对白和结局。

## 第一季时长与剧情边界

- 仍然是 **D-7 到 D+7**，**不增加第二季**，不无限循环重生。
- 建议表现为 16 个“短剧式章节节点”，每个节点包含 1 个主剧情事件和 1 个可玩衔接事件；再加可选支线。过场短、互动长。
- 目标完整首季体验约 2–4 小时**只是策划预测**；最终取决于真实玩法速度，不能当做已经测试的宣传事实。
- 季终是完整第一季结局，不以“先挖大坑不收尾”强迫进入第二季。

## 状态与命名兼容

- 保留 v1.0 `extra_cash/shared_spare_key/chen_helped/tang_helped/meng_helped/meng_exposed/han_helped/radio_repaired/share_heat/help_count/comfort_score`。
- 新增 `delivery_saved`, `grandma_plan_found`, `neighbor_water_helped`, `door_alarm_installed`, `wiring_inspected`, `last_shipment_received`, `heated_meal_made` 等事件旗标；默认 false。
- 新剧情的奖励不得重复给已有 P/D 事件的奖励；`seen_events` 按完整 ID 去重。
- 所有交易/选择有最小资源与 AP 校验；资源不足必须有无成本替代选项。

### v1.1 额外数值/规则补丁

- `P04B` 新增低成本“门口提示铃”：计划价格 **600 游戏元**，只提供开门警报与 D+5 的提示反馈，不额外增加保温。它是安装设施，不能通过反复拆装刷 flag。
- `P02B` 在超市内提供一次“临时批发预约”，并不提前开放 D-4 才出现的独立批发仓。
- `P07B` 新增**仅 D-1 五金店大件订单**的延迟配送事件：该笔门/密封材料订单支付后可进入 `pending_delivery`，需事件里取货、用早期预约服务优先配送，或原路退款；其他普通购买沿用 v1.0 的即时配送。退款与到货相互排斥，防止资源复制。
- `D01B` 的电力优先级只用于当天启动开关，实际能源消耗继续使用 v1.0 的发电/电暖器规则，不额外发明复杂电网模拟。
- `S10` 必须保留门口通路，不允许把所有仓储物资堆在门前导致无法完成剧情。

## 交付先后

1. 开发 Agent 完成初始化并给出截图/工程结构；我们审核。
2. 我这边确认原创新主角的立绘比例、统一角色风格、主要场景模块。
3. 开发 Agent 用**占位素材**建立购物→入库→建造→过夜的闭环；不依赖美术素材齐备。
4. 本包的剧情按事件 ID 导入，素材按资产表逐批替换；每一批测试画面一致性。
