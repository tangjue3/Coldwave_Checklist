# TASK-UI-005 · HUD 字体 A/B 方案对比

时间：2026-11-13　分支：`界面与UI`　范围：**只做字体预览，不接正式 HUD**

上一版（TASK-UI-004）视觉验收未通过，判定"过于厚重"。本轮整组重做字号与字重，出两套方案。

## 一、改了什么

| 层级 | 上一版（未通过） | 本轮 |
|---|---|---|
| 面板标题 | 21px / 宋 600 / 描边 3px @55% / 阴影 blur2 | **18px / 宋 600 / 描边 2px @40% / 阴影 blur1 @22%** |
| 正文标签 | 16px / 宋 400 / 描边 2px @45% | **14px / 宋 400 或 楷 400 / 描边 1px @32%** |
| 数值 | 17px / 宋 600 / **金色** / 描边 2px | **14px / 400 字重 / 米白** / 描边 1px 或 0 |
| 长数值（负重） | 12px 宋 600 | 12px 400 字重 |
| 已完成行 | 17px 楷 / `#C9BCA4` | 14px / `#A89B85`（仍可读但明显次要） |
| 画面标题 | 28px 楷 加粗 + 4px 描边 | 本轮不做（不在两块面板里） |

Black（900）字重两套方案都不用；SemiBold 只出现在面板标题上。

## 二、两套方案

**A · 精致宋体**
标题 宋 600 18px，正文与数值全部宋 400 14px，1px 深色描边，米白 `#E6DDCB`、数值 `#F4EBD8`。
描边存在感很低，作用是压住面板底与背景交界处的高频噪声。

**B · 宋体标题 + 霞鹜文楷正文**
标题同 A；正文、数值、已完成行全部换霞鹜文楷 400 14px，**取消描边**、阴影归零。
楷体笔画细，1px 描边会糊笔画；去掉描边后反而更清爽，面板底色本身够暗，对比度足够。

## 三、实机验证（960×540 原生）

- `ui005_ab.png` — 两套方案同框，各占一行，按游戏里真实位置摆（今日清单左上、生存状态右上）
- `ui005_a.png` / `ui005_b.png` — 单方案整屏，取景一致，便于逐像素比对
- `ui005_zoom.png` — 两块面板 3× 放大，看字形差别用

正文 14px、标题 18px 在 960×540 下折合 1080p 的 28/36px，比概念图等比缩下来的 7–10px 清楚得多。
没有为了"贴概念图"把字缩到看不清。

## 四、结论与建议

- 两套都能读，**A 更锐、B 更软**。A 的宋体笔画末端有锐角，缩放到 960 仍然干净；
  B 的楷体更耐看、更像"人写的清单"，但小字号下对面板底色的依赖更强。
- 若后续 HUD 面板会做成**深色半透明**（当前 StyleBox 就是），B 可行；
  若面板改成**浅色清单纸**，B 的楷体需要重新加深色描边，否则会漂。
- 两条硬建议：① 数值不要再回到金色，金色留给进度条与选中态；② 已完成行不要降到几乎看不见，
  它是"读过的证据"，不是禁用项。

## 五、待裁定

1. A 还是 B（或 A 的正文 + B 的任务行混搭）。
2. 面板最终是深色半透明还是浅色清单纸——这条会直接决定 B 能不能用。
3. 数值是否需要等宽（tabular）对齐：当前宋体数字不是等宽，多行右对齐时个位数会有 1px 抖动。
