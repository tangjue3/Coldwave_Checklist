## 一、任务书八问

### 1. 当前 Godot 版本能否可靠支持目标骨骼制作方案？

**能。** 项目实际版本 `Godot 4.7.2 stable`（`config/features=PackedStringArray("4.7","GL Compatibility")`），
本轮全部用引擎原生节点实现，没有第三方插件、没有运行时依赖：

| 需求 | 落地方式 | 实测结论 |
|---|---|---|
| 骨骼层级 | `Skeleton2D` + `Bone2D` ×18 | 父子关系与 spec 逐条一致（用例 6） |
| 刚性部件绑定 | 每个 `Bone2D` 挂一个 `Sprite2D` 子节点 | 静止姿态渲染与源图**逐像素相等（0 px 差异，用例 9）** |
| 关键帧动画 | `AnimationPlayer` + 运行时生成的 `AnimationLibrary` | 待机 / 行走两条动画，各 19～20 条轨，循环播放正常（用例 10–14） |
| 脚掌接地 | 解析二骨 IK（GDScript 手写，不依赖引擎 IK 节点）+ 30Hz 烘焙 | 支撑脚世界滑移 **0.042 px/帧**（用例 20） |
| 骨骼调试 | 自绘关节圆点 + 骨线（F1） | 见 `rig001_bones_debug.png` |
| 三倍最近邻预览 | `scale=3` + `Nearest` | 见 `rig001_zoom3.png` |

补充说明：Godot 4 的 `SkeletonModification2DTwoBoneIK` 存在，但**本轮没有采用**——
刚性 Cutout 的腿只有两段，解析 IK 计算量极小且完全可预测（没有求解器抖动、没有引擎版本兼容风险），
用 15 行数学解出来更可控。这一点可在下一轮换成引擎 IK 做对比。

### 2. 现有许知夏原图哪些部件可以直接利用？

基准图是 `ART_CHAR_001_r02_walk_right_00_contactA.png`（四帧行走里的接触帧）。
它是**唯一**能用的：r01 站姿两腿完全重叠（后腿一个像素都取不到），r03/r04/r09 是扶车姿态（手臂前伸）。

| 可直接利用（轮廓完整） | 图层 |
|---|---|
| 完全可用，无需补画 | `head`、`hand_near`、`hand_far`、`foot_near`、`foot_far`（5 层，补绘 0 px） |
| 基本可用，只需修补被压住的边 | `torso`、`arm_near_upper`、`arm_near_fore`、`leg_near_upper`、`leg_near_lower`、`leg_far_lower`、`ponytail` |
| 只能拿到一部分 | `pelvis`、`arm_far_upper`（整段被躯干挡）、`leg_far_upper`（上段被近腿挡） |

关键事实：**源图是单一连通体（4732 px 一块）**，马尾在 y=13–21 与后脑相连、手臂压在外套上、两腿在 y<118 并在一起。
任何"按连通块抠图"的做法都会失败，所以本轮改用**骨轴几何归属**切分（每个像素归给"距离/半宽"最小的骨）。

### 5. 行走动作是否达到了技术可验证的程度？

**达到了，而且脚掌接地是"算出来的"而不是"调出来的"。**

做法：先定义脚掌在画布里的轨迹（支撑相沿 −x 匀速后退，等价于身体前进；摆动相沿 +x 抬脚前摆），
再用**解析二骨 IK** 反解髋/膝角，最后按 30Hz 采样烘焙成 `AnimationPlayer` 的关键帧。
所以支撑相脚踝的世界坐标恒定性是可证明的，画面滑移只来自像素取整与关键帧线性插值。

步态参数（写在 spec 里，改一行就能换）：

| 参数 | 值 | 依据 |
|---|---|---|
| 循环 | 1.00 s | 走路常态 |
| 支撑相占空比 | 60% | >50% 才有双脚支撑，符合"走"不是"跑" |
| 步距（支撑相行程） | 42 px | 源图接触帧两踝间距实测 41 px |
| **设计步速** | **70 px/s** | `42 / (0.6 × 1.0)` |
| 抬脚高度 | 6.5 px | — |
| 骨盆起伏 | ±0.75 px（每循环两次） | — |
| 摆臂 | ±18°（与同侧腿反相） | — |
| 马尾跟随 | ±6°，相位滞后 0.5 | — |

### 6. 是否还有明显的接缝、像素闪烁、脚底滑动问题？

| 项目 | 结果 | 判定 |
|---|---|---|
| 支撑脚世界滑移 | 均值 **0.042 px/帧**，最大 0.38，样本 279（240 物理帧 / 2 个循环） | 通过（r09 逐帧方案为 1.29 px/帧） |
| 上体封闭孔（颈/肩/腋/肘） | 8 个相位合计 **18 px**，单帧最差 **3 px** | 通过（阈值 20 px） |
| 腿间背景缝 | 116 px（8 相位合计） | **不算缺陷**：两腿交叉时正常背景缝会短暂闭合，已单独统计 |
| 循环首尾连续 | 各骨角度最大差 **0.00000 rad** | 通过 |
| 全身高度稳定 | 159.2 → 161.3 px（波动 2.1 px） | 通过 |
| 头部水平漂移 | **0.31 px**（加了颈部平移补偿后） | 通过 |
| 像素闪烁/走样 | 所有旋转角 ≤20°，未见异常；**>30° 会有边缘抖动**（像素风骨骼固有问题） | 已知限制 |

**仍然存在的视觉瑕疵**（如实列出，不当作通过）：

1. 肘/膝内侧有 1–2 px 台阶（刚性 Cutout 的固有现象，8 相位最差 3 px）；
2. 肩腋处的手臂摆动时，外套上会露出"用袖子像素顶替"的近似色块——这是 §3 的 620 px 补画区；
3. 远侧上臂现在整段是**外套灰的占位色**（源图里它完全不存在），动起来材质不对；
4. `rig001_zoom3.png` 里能直接看到袖口与袖根的接缝。

### 7. 需要美术总监下一轮交付哪些具体图片？

## 四、过程中发现并修掉的问题（值得记录）

1. **骨盆坐标系错配（整身偏 107 px）**：spec 里 `root` 骨静止角 −90°，骨盆是它的子级；
   动画把骨盆位置按**画布坐标**写进去，结果被父级旋转转了 90°，整个角色右移 107 px。
   *这个问题静态姿态查不出来*（静止走建树逻辑），只有播动画才暴露。
   修复：写轨前用 `(pelvis_pos - root_origin).rotated(-root_rest_rot)` 转进父级坐标系；
   并补了一条 **"动画首帧脊柱链坐标 == spec 关节坐标"** 的断言，专门抓这类错误。
2. **胶囊半径吞掉邻肢**：初版用圆头胶囊定部件区域，头部把肩膀、躯干把脖子都吞了进去，
   旋转时会带动不该动的部位。改为**矩形带**（沿骨轴、两端留 2–4 px），并按肢体给 tip 端更大外扩量补关节缝。
3. **诊断图合并成一张等于没用**：需补绘掩码最初合并成一张，结果是"整身都是洋红"。
   改成**逐层各一张**（`diagnostics/repaint/<layer>.png`）才对美术有指导意义。
4. **PCK 体检被自己的注释绊倒**：测试脚本里写了素材目录的路径字面量（甚至注释里也写了），
   被 GDScript 源码打进 PCK，触发 `check_art005e_pck.py` 的黑名单。
   修复：运行时不读该目录，把「未登记台账」这条断言挪到构建期（Python）校验。
