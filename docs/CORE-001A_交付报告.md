> 任务来源：`转存库/CORE-001A_发给开发Agent.md`（创意与美术总监签发，用户委托开发 Agent 落地）。
> 阶段：SCALE-001 验收通过、生产尺寸批准后。**本轮只做移动底座与单帧接入试验，不做玩法。**

> 货架 96×192 四层 / 购物车长 96 / 主通道 192 / 小包装 32×32 / 大包装 64×48、64×64 / 电暖器 64×96。
> 28 px 碰撞宽为**实机起测值**，本轮未改动任何已锁定的视觉尺度。

### 三条必须让策划知道的结论

**① 碰撞必须分两层，门不能当通行缺口。**
严格侧视里，门、超市入口、货架都贴在墙面/景深处，玩家是从**前面走过**，不是在 x 方向"穿过门洞"。
把门框当碰撞体，人物会被挡在门框外侧（实测停在 x=286，门洞在 308–388），根本走不进门洞。
因此：**门是交互点（按 E 进门），不是碰撞缺口**；货架同理属于背景层。

**② 单行走线 + 不能跳跃 ⇒ 行走线上的物件是硬墙。**
购物车放在通道里，人物会被挡停（实测停在 x=1030），**192 的通道净宽买不到"绕过去"**。
SCALE-001 里"通道 192、车 96、余 96"是**视觉拥挤度**的度量，不是可通行性。
要么购物车/货架全部画进背景层，要么给推车单独一套"推开 / 绕行"的交互——这是 CORE-001B 的决策点。

**③ 单帧贴图质量过关，但它只是"站着"的一张。**
行走、转身、搬运、推车动画都没有；朝左是**临时镜像**，且因画布左右不对称（左 43 / 右 44），
翻转后包围盒整体右移 **1 px**，正式左右动作仍需美术按 128×176 同锚点出帧。

**观察到的、需要在正式关卡设计时处理的问题**

1. **门在背景层**：门洞是纯暗色块，人物从前面走过去并不"进入"。正式关卡里门需要接入交互提示（按 E），

4. 叠加层的红色"碰撞 28"在深棕墙面上对比度偏低（诊断信息，不影响玩法）。

## 4. 量测数据（运行时实测，非手填）

```
[CORE] 纹理 128×176  节点 scale=(1.0, 1.0)  filter=1(Nearest)
[CORE] sprite.get_rect() = [P: (-64.0, -168.0), S: (128.0, 176.0)]   期望 (-64,-168,128,176)
[CORE] 可见包围盒(实测 alpha) = 41×160 @ (43,8)   本地 (-21,-160)
[CORE] 碰撞盒 = 28×160 @ (-14,-160)
[CORE] alpha 档位 = [0 255]（2 档）无半透明，边缘干净
[CORE] 脚底误差 = 0.0 px（可见框底边 0.0 vs 原点 0）
[CORE] 住宅门 净 80×184 → 碰撞 28 宽：左余 26 / 右余 26；头顶余 24
[CORE] 超市主通道 192，购物车 96 → 单侧可通行 48（碰撞 28）
[CORE] 世界地面 y=0，当前屏幕 y=334（HUD 在 CanvasLayer，不影响世界地面）
```

| 对比项 | 数值 | 判断 |
|---|---|---|
| 可见宽 vs 碰撞宽 | 41 vs 28 | 碰撞比剪影窄 13 px，左侧多 7、右侧多 6（剪影本身不对称） |
| 门净宽 vs 碰撞宽 | 80 vs 28 | 每侧余 26，**不会卡死** |
| 门净宽 vs 可见宽 | 80 vs 41 | 每侧余 19.5，**视觉上也是"人从门里过"** |
| 门净高 vs 可见高 | 184 vs 160 | 头顶余 24（15% 身高），**不裁切** |
| 通道 vs 车 | 192 vs 96 | 单侧空档 48 > 碰撞 28，但**视觉余量按剪影算只有 7** |

> 碰撞盒 = 28×160，与可见高度相同；只比剪影窄。这是有意的：碰撞决定"能不能过"，剪影决定"看着挤不挤"。

## 5. 三组实机测试

### T1 门 · 背景层（默认模型）

`240 → 460`，最长停滞 **0 帧 → 通过**。门是墙面元素，玩家从前面走过，不会在门口被卡。

### T2 门 · 门框当实体（A/B 对照）

临时给门框加碰撞后，同样从 240 往右走：**停在 x=286，理论值 286**（门框外沿 300 − 半宽 14）。
数字完全吻合，说明碰撞本身是准的；**结论是建模问题，不是数值问题**：

> 侧视里把门当 x 方向的通行缺口，人会永远顶在门框外侧。门必须是交互点。

### T3 购物车 · 硬障碍

`980 → 停在 1030`，理论值 1030（车左沿 1044 − 14）。**购物车在行走线上就是墙**，
192 的通道宽不改变这一点。这是要给策划拍板的第一个设计问题。

### T4 相机死区

| 指标 | 值 |
|---|---|
| 死区 | 56 × 28（半宽/半高） |
| 平滑 | 8.0（≈0.12 s 收敛 63%） |
| 视线偏移 | (0, −64) ⇒ 人物落在画面偏下、地面线在屏幕 y=334 |
| 180 帧内相机移动 | 144 帧 |
| **死区内误动** | **0 帧** |
| 最大偏移 | 69.4 px |
| 稳态滞后理论值 | 死区半宽 + 速度/平滑 = 56 + 100/8 = **68.5 px** |

实测 69.4 与理论 68.5 差 0.9 px，属于 60 fps 下的离散误差。**死区生效：目标在死区内时相机一帧都不动。**

> 这些参数是**待调项**：写死在 `follow_camera.gd` 的导出属性里，没有进美术数据，也没有假设 y=416。
