## 一、这轮到底做了什么

三件事：**把素材库的自洽性做成可校验的**、**把总览页改成能按动作/按状态筛的工具**、
**把 AI 视频接入的规范和工具先搭好等视频**。

一句话概括问题意识：之前的素材库不是「内容错」，而是「**描述和事实分家**」——
台账、README、手抄索引各自记着不同时间点的状态，谁也没错，但谁也不对。
这轮不是修内容，是**建立一套能自动发现「描述≠事实」的机制**，并把已经分家的地方改回来。

## 四、视频接入准备（本轮不生成视频）

### 4.1 规范

[`docs/AI视频转Godot动画接入规范.md`](../docs/AI视频转Godot动画接入规范.md)：
分工边界、工程约束、视频交付要求、处理链路、12 项全量验收清单、
转正六步流程、6 条必须退回的情形、已知缺口。

### 4.2 工具

`tools/video/pipeline.py` —— 六个子命令，可单跑也可 `all`：

```
probe → extract → matte → analyze → align → build
```

- `probe` ffprobe 拍参数，先判断值不值得做（太小 / 太短 / 帧太多直接提示退回）
- `extract` 抽全部原始帧（`-vsync 0`，不丢帧不重复）
- `matte` 四角中位数估背景色，软阈值抠像，透明像素 RGB 清零防色边
- `analyze` 包围盒高度/宽度波动、脚底行稳定、重复帧、按速度推算逐帧位移
- `align` **整数最近邻**缩放 + 水平居中 + 脚底贴 (64,168)，禁止非整数缩放
- `build` 接触表（一行 8 帧）+ 循环 GIF

`tools/video/selftest.py` —— 合成一段测试片跑完整链路，断言 11 项后删掉临时目录。
本机实测**全绿**，证明这条链路真的能跑，不是纸面方案。

### 4.3 引擎内验收场景

`scenes/dev/video_preview.tscn` + `scripts/dev/video_preview.gd`，`--dev-scene=video`，
**隔离运行，不参与玩法、不替换任何动画**。

- 直接读 `frames_out/` 的 PNG（`Image.load_from_file`，**不需要先 import**）
- 画地面 32px 刻度 + 脚底锚点红十字，`M` 键按速度真实移动，看滑步最直观
- 空格播放/暂停、`1/2/3` 切缩放（Nearest，像素不糊）、`←/→` 逐帧
- `--video-test` 跑 8 项体检，退出码即结论

用 r09 的 16 帧当临时候选实测：8 项全过（脚底行恒为 167，距锚点 168 差 1px，
在 ±2 容差内；包围盒高度波动 0.0%）。

### 4.4 一条重要的口径纠正

规范里原本按「推车 80 / 拉车 40」写，我核对代码后确认：
`PlayerController.move_speed = 100`，`PushableCart.push_speed = 80`、`pull_speed = 40`。
三个数值都在，只是分属两个类。**已按代码实际情况写进规范 §1，并注明动不得。**

同时记录一条**未裁定冲突**：ART-RIG-001 的步态按 70 px/s 推演，与 100 px/s 不等。
本轮不裁、不改，只在规范和报告里挂出来，等总监定。

## 七、给下一条视频的交接清单

用户生成完视频后，交给开发 Agent 只需要说一句「视频在哪、做什么动作」，剩下按规范走：

```bash
# 1. 一条命令跑完抽帧到对齐
python tools/video/pipeline.py all <视频路径> --batch walk_right --action walk --fps 10 --speed 100

# 2. 引擎体检
.tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . -- \
    --dev-scene=video --video-dir=walk_right --video-fps=10 --video-test

# 3. 出审核截图
.tools/godot/Godot_v4.7.2-stable_win64_console.exe --path . -- \
    --dev-scene=video --video-dir=walk_right --video-tour
```

体检全绿才交审核；审核通过才转正；转正必留回退。
**本条链路的终点是「候选 + 证据」，不是「改默认动画」。**
