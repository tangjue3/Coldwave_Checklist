## 3. 对数据结构的影响（供后续 STORY-001 / SHOP-001 参考）

v1.0 `03` 给出的事件数据形状只有两类 effects：`resource`（资源增减）与 `flag`（布尔置位）。
v1.1 的新事件还需要以下能力，落数据前必须扩展 schema：

| 需要的能力 | 出现位置 | 建议的 effect 类型 |
|---|---|---|
| 生成/收取/退款一笔延迟订单 | P07B | `create_delivery_order` / `collect_order` / `refund_order` |
| 单次临时运输额度 | P02B | `temp_cart_bonus`（带 `expires_day`） |
| 消耗行动点 | P02B、P07B、D02B、D04B | `ap`（与 v1.0「整理不耗 AP」并列，需显式声明） |
| 解锁楼层/区域 | P00B、D04B | `unlock_area` |
| 设置当天用电优先级 | D01B、D06B | `set_power_priority` |
| 放置教学型物件且不重复加标志 | P03B、P04B、D05B | 由 `once: true` + `seen_events` 保证，不新增类型 |

另外 `seen_events` 必须按**完整 ID**（含 `B` 后缀）去重；`C1` 的命名空间若不分，去重会直接误伤素材台账。
