# 《寒潮清单》开发交接包（策划初版 v1.0，待用户确认）

> 原创 2D 横版精细像素游戏：重生七天囤货、改造安全屋，在极寒末日中把上一世的结局改写。
>
> 日期：2026-11-08。本文是交给其他开发 Agent 的设计资料；**当前尚未开始开发**。名称、玩法、剧本、数值均为可调整的策划基线，并非已实现功能。

## 0. 给开发 Agent 的指令（可整段复制）

你将开发原创单机游戏《寒潮清单》（Coldfront Checklist）。请先完整阅读本目录全部文档，以本文、GDD、剧情、技术方案的顺序执行。游戏必须是 **真正可操作的 2D 横版像素游戏**，不是网页 PPT、静态演示，也不是纯文字选择游戏。核心闭环是“走进商店采购 → 物资回家入库 → 亲手摆放与升级房间 → 结束一天 → 触发剧情和生存结算”。

**技术基线：Godot 4.7.2 stable（或同系列后续稳定修订）+ GDScript，不用 C#；原生 Windows 首发，保留 Web 试玩导出。** 纯离线可玩，首个版本不需要任何付费 AI API。先以占位像素素材实现流程，再逐步替换成统一画风；参考图只作美术风格指引，禁止未经许可直接复制他人角色/游戏资源。所有剧情、数值、可交互物品和日程必须数据驱动。

每个开发阶段请先写出可验证的验收清单；完成后实际运行游戏，修复阻断性问题，再进入下一阶段。严格区分“已经实现”和“暂未实现”。**不要因为要赶进度就把剧情整合成几张静态幻灯片；也不要提前加入多人、开放世界、战斗、无限循环重生、随机 AI 生成全剧情等未要求功能。**

## 2. 已确认的用户需求（优先级最高）

1. **真正的 2D**：非 3D、非伪 3D；横向侧视，购物场景和建筑剖面式安全屋。
2. **美术**：偏写实的正常人物比例；精细手工像素、清晰暗色轮廓、灰棕/暗绿低饱和配色；室外极寒蓝灰与室内暖黄色灯光对比。参考用户提供的角色图，不直接复制角色身份。
3. **玩法**：购物与建造相结合。角色可以走动、靠近货架购买，回家能实际陈列物资和安装家具/设备；建设成果实时可见。
4. **剧情**：正常、易懂、有爽点的末日重生短剧套路：上一世冻死 → 回到七天前 → 囤货被嘲笑 → 末日到来 → 求助者上门 → 主角在安全屋内逆袭。
5. **开发方式**：用户负责策划确认，另一位 Agent 负责具体实现；当前交接包不包含游戏工程代码。
6. **目标**：先做一款完成度高、能玩且有传播片段的独立游戏，同时留有参与 AI/游戏黑客松的可演示版本。

## 3. 暂定产品承诺

- 中文名：**寒潮清单**；英文工作名：**Coldfront Checklist**。
- 宣传标题：**重生回末日前七天，这一次，我把外婆留下的旧小楼改造成了安全屋。**
- 主角：许知夏（原创女性角色）；后续若更换人物，不影响核心机制。
- 题材：极寒天灾，非丧尸大战；不含魔法空间仓库或无限物资外挂。
- 时间线：灾前 7 天（D-7 至 D-1）+ 降临日（D0）+ 灾后 7 天（D+1 至 D+7），形成**第一季完整故事**。
- 设计体验：约 60–120 分钟的首季剧情与经营，取决于阅读和布置时间；黑客松切片约 8–15 分钟；不是已验证时长。
- 平台：PC/Windows 优先，兼顾 macOS/Linux；通过 Godot Web 导出做网页试玩验证；移动端暂不承诺。
- 商业/发布：初期不设计内购或付费抽卡，不接入在线账号/服务器；发行与盈利方案待试玩反馈再决策。

## 4. 当前核心卖点与竞品规避

市场已有其他“预知灾难、囤货、基地经营”游戏；本项目不能只替换其人物和剧情。重点做出差异：

1. **看得见的囤货**：购买的物资在仓库中以箱、罐、袋、瓶等可见堆叠形式展示；储物空间有真实占格和视觉反馈。
2. **横版剖面楼房生长**：从外婆留下、仅一层可住的两层旧小楼升级到上层生活区/下层设备区，玩家能一眼看出自己比开局富足多少。
3. **短剧反差展示**：外部雪灾、邻居求助和内部温暖生活同步呈现；剧情表现短、快、有记忆点。
4. **一次重生 + 线性章节**：不是不断清零的 Roguelike；玩家保留辛苦建好的基地，结局由建设和选择共同决定。

## 5. 范围与不做的事情

**第一阶段必须完成：** 角色横向移动、1 个商店、购物车和结账、物流入库、1 个可摆放的安全屋、物品与设施、时间/资源结算、3 个剧情事件、存档、1 个有输赢的生存日、可操作的 UI。

**第一季目标：** 3 类商店、住宅 2 层、约 15 类采购物品、10 种设施、全主线 15 个日程节点、若干支线、3 个存活结局和 1 个失败结局。

**不做：** 第一/第三人称 3D、开放世界、车辆驾驶、多玩家联机、实时战斗、复杂物理模拟、AI 实时决定经济数值、几十个不能交互的假地点、需要用户填 API Key 才能运行的核心体验。

## 6. 原创和权利要求

- 市场流行的“重生、囤货、极寒、打脸”属于题材惯例，但**剧名、主角、对白、场景、视觉素材**必须独立原创。
- 用户给的人物图是**风格参考**，不是确认拥有商业复用权的角色资源；不直接抠图、追摹后发布，也不照搬其他游戏的界面布局、素材和代码。
- 上线前应核对名称、商标、字体/音效/素材授权及平台规则。工作名并不代表完成商标可用性审查。
