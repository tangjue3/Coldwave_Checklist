## 2. 像素渲染设置（已生效，勿随意改）

| 设置项 | 值 | 说明 |
|---|---|---|
| `display/window/size/viewport_width/height` | 960×540 | 内部逻辑分辨率 |
| `display/window/stretch/mode` | `viewport` | 画面整体放大 |
| `display/window/stretch/scale_mode` | `integer` | 只允许 1×/2×/3×，避免像素边缘错位 |
| `display/window/stretch/aspect` | `keep` | 窗口不是 16:9 时居中留黑边，不拉伸变形 |
| `rendering/textures/canvas_textures/default_texture_filter` | `0` (Nearest) | 全局最近邻采样 |
| `rendering/2d/snap/snap_2d_transforms_to_pixel` | `true` | 抑制亚像素抖动 |
| `environment/defaults/default_clear_color` | `#1B2026` | 暗炭灰底色 |

**发布版不写死初始窗口尺寸**：`project.godot` 没有 `window_width_override` / `window_height_override`。
由 `scripts/dev/window_fit.gd` 在启动时读取「窗口所在显示器的可用区域」，取能放进去的最大整数倍作为窗口尺寸，并按虚拟桌面坐标居中。

> 多显示器坑：`DisplayServer.screen_get_usable_rect()` 返回的是**绝对坐标**（例如第二块屏 origin=(1600,0)）。
> 居中必须用 `rect.position + (rect.size - window_size)/2`，只用 `screen_size/2` 会把窗口摆到另一块屏上。

全屏时窗口本来会盖住任务栏，判断「是否超屏」要改用整屏矩形而不是可用区域，见 `WindowFit.comparison_rect()`。

## 3. 中文字体与 UI Theme（已完成）

| 项 | 落地结果 |
|---|---|
| 字体 | `assets/ui/fonts/NotoSansSC-Variable.ttf`（17.77MB，完整简体中文 + 拉丁 + 符号） |
| 授权 | `assets/ui/fonts/OFL.txt`（SIL Open Font License 1.1）随工程与导出包分发 |
| 导入参数 | `.ttf.import` 中 `allow_system_fallback=false`，缺字会暴露而不是悄悄用微软雅黑补 |
| 全局 Theme | `assets/ui/themes/main_theme.tres`，由 `scripts/dev/generate_ui_theme.gd` 生成 |
| 挂载方式 | **PREP-003 起**：由 `UiTheme` autoload 在运行时 `get_tree().root.theme = load(THEME_PATH)`。**不要**在 `project.godot` 里设 `gui/theme/custom` |
| 覆盖范围 | default_font、Label / RichTextLabel / LineEdit 文字色与行距、Button 四种状态、Panel 样式 |

> **为什么改挂载方式**：Godot 4.7 的 `ThemeDB::initialize_theme()` 在资源导入**之前**读取 `gui/theme/custom`；
> 全新 `.godot/` 里字体尚未生成 `.fontdata`，主题却通过 `.ttf` 引用它，于是第一次 `--headless --import`
> 打印 7 条 `Failed loading resource / Error loading custom project theme`。去掉项目级设置、改运行时挂载后，
> 独立全新副本第一次导入即 0 报错，字体与显示效果完全不变。自检里有两项专门防止把该设置加回来。
> `UiTheme` 必须用 `load()` 而不是 `preload()`，否则脚本扫描阶段又会提前解析主题。

**不要用 `SystemFont` 回退**，也不要在场景里逐个 `theme_override_fonts/font`：全局 Theme 已经统一处理。
新增 UI 控件直接继承即可。字体子集化会改变 OFL 合规条件，做之前先看 `assets/ui/fonts/README.md`。

> **坑（CORE-001B 修）**：`get_tree().root.theme = ...` 只对**当时已在树上**的节点完成传播。
> 之后用 `change_scene_to_file` 载入的新场景拿不到主题：桌面端有系统字体兜底，中文看起来正常，
> 所以 PREP-003 到 CORE-001A 一直没暴露；**Web 端没有系统字体兜底，换场景后整页变成方块**。
> 现在 `SceneRouter.goto()` 成功后调用 `UiTheme.reapply_after_scene_change()`：轮询等新场景挂上
> （`current_scene` 会先变成 null，等一帧是不够的），再把主题递归挂到场景里所有"没有自己的 theme"的 Control 上。
> 只重挂 Window 级主题**无效**——已在树上的 Control 在入树时就绑定了 theme owner，不会再重新解析字体。
> 新增会切场景的入口时，务必继续走 `SceneRouter.goto()`，不要直接 `change_scene_to_file`。

## 4. 输入映射

动作名固定，脚本只引用动作名，不写死按键：

| 动作 | 按键 | 用途 |
|---|---|---|
| `move_left` / `move_right` | A / ← 、D / → | 横向移动 |
| `interact` | E | 货架、收银台、设施、NPC |
| `toggle_inventory` | Tab | 清单/背包 |
| `toggle_build_mode` | B | 家中建造模式 |
| `pause` | Esc | 暂停 |

使用 `physical_keycode`（按物理键位），在非 QWERTY 布局或中文输入法下也不会失效。

> **Godot 4 键码坑**：特殊键基址是 `1<<22 = 4194304`，不是 `1<<24`（bit24 是 CTRL 修饰位）。
> Esc=4194305、Tab=4194306、Left=4194319、Right=4194321。自检脚本会逐一比对期望键名，写错立刻报错。

## 5. 目录与命名

- 场景 `snake_case.tscn`，脚本同名 `snake_case.gd`，节点用 PascalCase。
- `scenes/` 只放场景，逻辑放 `scripts/`；`tools/` 放复现与测试脚本（不参与游戏运行时）。
- 美术资源按 `assets/{characters,tiles,items,facilities,ui,audio,portraits}` 分类，文件名用小写英文 + 下划线。
- 数据一律放 `data/*.json`，由脚本读取；不要在脚本里硬编码物品价格、抗寒数值、台词。
- 预留目录用 `.gitkeep` 占位；`tests/screenshots/`、`docs/`、`builds/`、`素材库/` 放 `.gdignore`，避免引擎把测试截图、文档和美术设定库当资源导入。
- **`素材库/` 是纯资料库**（ARTLIB-001）：根目录 `.gdignore` 让整棵树对 Godot 不可见。禁止任何脚本写 `res://素材库/...`。
  正式资源只能来自台账中 `审核状态 = 运行时可用`、登记了 `对应运行时资源路径`、且该文件真实存在的条目，详见 `素材库/README.md`。
  改动台账或图片后执行 `python tools/build_artlib.py` 重建离线预览页。
- **版本号有两套序列**：`vNN` 是设定 / 概念版本（v01、v02…），`rNN` 是运行时候选 / 运行时版本（r01…），
  美术交付包用 `r`。状态后缀（`v01-base`、`v01-empty`）只写在台账里，**不写进文件名**。
- **素材编号以 `素材库/ID登记表.csv` 为准**（SCALE-001 起）：每个号只有 `已用` / `预留` / `空置` 三种状态。
  生成任何素材前先查 `素材库/ID登记表.md` 的「下一可用号」；新号先在 CSV 登记，再动文件与台账。
  `python tools/check_id_registry.py` 校验登记表、台账、文件名三者一致，非 0 退出即不得提交。

### 7.0 角色移动底座（CORE-001A）

`scenes/characters/player.tscn` + `scripts/characters/player_controller.gd` 是**可复用**的横向移动组件：
水平移动 / 停下 / 朝向 / 碰撞 / 脚底接地，不做跳跃、重力、攻击、平台动作。
配套 `scripts/characters/follow_camera.gd` 提供参数化死区 + 平滑跟随。

- 节点原点 = **脚底**；sprite `centered=false`、`offset.y=-168`，把 128×176 纹理的 (64,168) 钉在原点；
- 贴图固定 **1:1 + Nearest**，禁止用 scale 或小倍数"修"尺寸；
- 地面线由导出属性 `ground_y` 给出，**不假设**视口里有固定 y=416；
- 碰撞盒 28×160，只有宽度会随实机测试调整。

**角色渲染：当前为空（ART-RESET-001，2026-11-10）**

- `assets/characters/` 整目录与 `player_sprite_frames.tres` 已删除；`player.tscn` 的
  `Sprite` 节点保留（`visible=false`、`centered=false`、`offset=(-64,-168)`），
  将来换上新 SpriteFrames 即可，锚点约定不变。
- `PlayerController` 去掉了动画状态机、`push_anim_variant` 切换与绘制对齐计算。
  保留：水平移动 / 停下 / 朝向 / 碰撞 / 脚底接地 / 外部接管（推车）/ 输入覆盖 / 传送。
- `state`、`push_pose`、`push_walk_active` 三个状态**仍在**并仍由 `PushableCart` 驱动，
  只是不再驱动任何帧；接新动画时在这里接上即可，交互逻辑不用改。
- `has_visual()` 返回 false，测试用它区分「功能通过」与「美术缺失」。
  启动会打印一次 `[PLAYER] 角色渲染为空：ART-RESET-001 …`。

> 为什么删得这么干净：旧 r 系列的人物形象已与 v02 设定跑偏，留着"回退版本"
> 只会让人以为它还能用。要追查请走 Git 历史（工作区不留副本）。

实验场景 `scenes/dev/core_001a.tscn` 用来验证这套底座：灰底轮廓 / 住宅门 / 暖色超市 / 主通道 / 冷色街景
五段，按已批准尺寸摆等比例占位。碰撞分两层：

- **背景层（不碰撞）**：门、超市入口、货架 —— 贴在墙面/景深处，玩家从前面走过；
- **实体层（碰撞）**：购物车、世界两端墙 —— 确实在玩家的行走线上。

> 这个分层是本轮的建模结论：严格侧视里门是墙面元素，玩家不可能在 x 方向"穿过"门洞；
> 把门框当碰撞体会让人物卡在门框外（实测停在 x=286）。门必须是**交互点**，不是通行缺口。

### 7.2 交互与购物车（CORE-001B）

交互只做一件事：**「站在这个范围内按 E 会发生什么」**，不引入交互状态机 / 条件系统 / 对话框架。

| 文件 | 职责 |
|---|---|
| `scripts/interaction/interactable.gd` | `Interactable extends Area2D`：提示文案 + `interact_priority` + `enabled` + `single_use`，`interact(actor)` 是唯一入口 |
| `scripts/interaction/door_interactable.gd` | 门：`target_scene` 指向 `SceneRouter` 的 key；`interactive=false` 即装饰门（无提示、按 E 无作用）；`single_use` 防连按重复加载 |
| `scripts/interaction/shelf_interactable.gd` | 货架：只发 `E 查看` 反馈，不打开任何界面 |
| `scripts/interaction/interaction_sensor.gd` | 每物理帧用 `Area2D.overlaps_body(玩家)` 选**唯一**目标并画提示；E 只派发一次 |
| `scripts/objects/pushable_cart.gd` | `PushableCart`：PARKED / PUSHING 两态骨架 |

选目标的规则必须稳定：`interact_priority` 大者优先 → 同优先级比水平距离 → 距离差 <1px 时用实例顺序兜底，
避免逐帧抖动。当前优先级：购物车 20 > 门 10 > 货架 5。

**购物车的三条硬约束**（都来自 CORE-001A 的实测结论）：

1. **停放时不是硬墙**：车没有任何物理体，玩家直接从它身上走过去；只有前后两层绘制（`z=0` 常驻 / `z=1` 只在
   与玩家横向重叠时显示）制造"侧身绕过"的观感，**世界坐标里的行走线一条都没变**。
   ART-INTEGRATE-002 起两层用的是**同一张真实精灵**（`ART_FURN_103`），车篮网眼透出裤腿；
   这是单张图的临时做法，正式前后分件交付后应替换。
2. **绑定后是刚体组合**：相对侧位 `side` 在绑定瞬间确定，之后永不翻面；按反方向键是"拉着车后退"（`pull_speed` 40），
   不是"车瞬移到另一侧"。
3. **撞墙整组停住但仍可解绑**：用 1px 子步 + 矩形 shape 查询（`collision_mask=1`，排除玩家自己）逐步试探，
   停下的位置一定是"车和人都没和墙体重叠"的位置。

参数：推速 80、反向 40、普通行走 100（前两个是待调项，不是美术尺寸）；脚底原点到车心 `side_offset = 80`。

## 9. Web 导出

- 预设 `export_presets.cfg` 已提交：`Web` / `variant/thread_support=false`（默认单线程）/ GL Compatibility / `export_filter=all_resources`。
- `include_filter` 里显式带上 `assets/ui/fonts/OFL.txt`——许可证文件不是 Godot 资源，不加就不会进 `.pck`，Web 自检会报 `[FAIL]`。
- `.wasm` 必须由静态服务器返回 `application/wasm`，`tools/serve_web.py` 已处理。
- 单线程导出**不需要** COOP/COEP 响应头；如果以后打开线程支持，必须给服务器补 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp`。
