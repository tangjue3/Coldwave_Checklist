# 开发说明（v0.1 工程底座）

这份文件记录**本工程实际采用的约定**，与 `docs/handover_v1.0/03_技术架构开发路线与验收.md` 配合阅读。
交接包是规划，本文是落地结果；两者冲突时以本文为准，并回头修正交接包。

---

## 1. 引擎与脚本

| 决策 | 取值 | 理由 |
|---|---|---|
| 引擎版本 | Godot 4.7.2 stable | 交接包指定；实测 `4.7.2.stable.official.ed1daf0bf` |
| 脚本语言 | GDScript | 4.x 的 C# 工程对 Web 导出不友好，本项目以轻量单机为目标 |
| 渲染后端 | `gl_compatibility` | 兼容旧显卡与浏览器 WebGL2，便于日后 Web 试玩 |
| 引擎存放 | `.tools/godot/`（git 忽略） | 仓库不放 180MB 二进制；换人接手时按 README 重新下载 |

**版本锁定**：`project.godot` 的 `config/features` 写死 `4.7`。不要用 4.6 打开后保存，会静默降级并改写工程文件。

## 2. 像素渲染设置（已生效，勿随意改）

| 设置项 | 值 | 说明 |
|---|---|---|
| `display/window/size/viewport_width/height` | 960×540 | 内部逻辑分辨率，交接包 GDD 8.3 的建议值 |
| `display/window/size/window_width/height_override` | 1920×1080 | 默认窗口尺寸 = 内部视口的 2 倍整数缩放 |
| `display/window/stretch/mode` | `viewport` | 画面整体放大，像素不会各放大各的 |
| `display/window/stretch/scale_mode` | `integer` | 只允许 1×/2×/3× 整数倍，避免像素边缘错位 |
| `rendering/textures/canvas_textures/default_texture_filter` | `0` (Nearest) | 全局最近邻采样 |
| `rendering/2d/snap/snap_2d_transforms_to_pixel` | `true` | 抑制亚像素抖动 |
| `environment/defaults/default_clear_color` | `#1B2026` | 暗炭灰底色，和暗色调美术方向一致 |

新增贴图时**不要**逐张改 Filter，全局已设为 Nearest；只对确实需要平滑的 UI 元素单独覆盖。

**整倍数缩放的副作用**：窗口尺寸必须是 960×540 的整数倍，否则会按 1× 渲染并在四周留黑边（`aspect=keep`）。所以默认窗口取 1920×1080（2×）；如果目标机屏幕小于 1080p，把 override 改成 960×540（1×）即可，不要用 1280×720 这类非整数倍尺寸。

## 3. 输入映射

动作名固定，后续所有脚本只引用这些名字，不要写死按键：

| 动作 | 按键 | 用途 |
|---|---|---|
| `move_left` / `move_right` | A / ← 、D / → | 横向移动 |
| `interact` | E | 货架、收银台、设施、NPC |
| `toggle_inventory` | Tab | 清单/背包 |
| `toggle_build_mode` | B | 家中建造模式 |
| `pause` | Esc | 暂停 |

使用 `physical_keycode`（按物理键位），所以在非 QWERTY 布局或中文输入法下也不会失效。
鼠标点击/拖拽直接走 Control 的 `gui_input`，不占动作槽。

## 4. 中文字体（**待处理项**）

Godot 内置默认字体不含中日韩字形，Label 直接写中文会显示方块。
当前 `scenes/dev/test_scene.tscn` 用 `SystemFont`（Microsoft YaHei → Noto Sans SC → PingFang SC 回退）临时解决，**只适合开发期自检**。

正式开发前需要：下载一份可商用授权的中文字体（如思源黑体 / Noto Sans SC，SIL OFL），放到 `assets/ui/fonts/`，在主题里设为默认字体，并保留授权文件。这件事在接入第一段真实剧情文本之前必须做掉。

## 5. 目录与命名

- 场景 `snake_case.tscn`，脚本同名 `snake_case.gd`，节点用 PascalCase。
- `scenes/` 只放场景，逻辑放 `scripts/`，禁止在场景里内嵌大段代码（自检脚本除外）。
- 美术资源按 `assets/{characters,tiles,items,facilities,ui,audio,portraits}` 分类，文件名用小写英文 + 下划线，不要中文和空格（跨平台与命令行友好）。
- 数据一律放 `data/*.json`，由脚本读取；不要在脚本里硬编码物品价格、抗寒数值、台词。
- 预留目录用 `.gitkeep` 占位，填内容时删掉。

## 6. 数据驱动约定

`data/` 目前为空。v1.1 交接包到位后按交接包 §3 的形状填充：

```text
data/items.json            物品（id / name / price / volume / stack_size ...）
data/facilities.json       设施（占用格、耗电、抗寒加值）
data/shops.json            商店与货架
data/economy.json          价格系数、每日所需抗寒、消耗速率
data/story_main.json       主线事件
data/story_optional.json   支线事件
```

**本阶段刻意不写这些文件**：v1.0 的数值已确认需要重平衡（资金/容量/行动点三个约束在初稿下全部失效），提前落数据只会带来返工。

## 7. 启动自检

`scenes/dev/test_scene.tscn` + `scripts/dev/startup_smoke.gd`：

```bash
.tools/godot/Godot_v4.7.2-stable_win64_console.exe --path .
```

会检查：引擎版本、内部视口尺寸、纹理过滤、缩放模式、渲染后端、像素对齐、6 个输入动作、主场景加载、图标与参考图可用性；随后把截图写到 `tests/screenshots/`，通过返回 0，有失败项返回 1。

改了渲染或输入配置后，先跑一遍自检再继续写代码。

## 8. Git 约定

- 分支：`main` 直推（单人开发期）。多人协作前再切 `feat/*`。
- 提交信息：`<类型>: <中文简述>`，类型用 `feat / fix / chore / docs / art / balance`。
- 不入库：`.godot/`（导入缓存）、`.tools/`（引擎二进制）、`*.zip`（原始交接包）、`export_presets.cfg`（含本机路径）。
- 每次提交前确认 `git status` 里没有 `tests/screenshots/` 之外的意外产物（截图目录保留，用于对比渲染回归）。

## 9. 下一阶段的前置条件

开工正式内容前，按顺序确认：

1. v1.1 交接包（剧本与素材规格升级版）到位。
2. 中文字体落地 + 授权记录。
3. 数值重平衡方案确认（开局资金、抗寒阈值、容量与行动点约束）。
4. 决定发行形态：Windows 单机包 or 网页试玩优先——这决定要不要现在就把 Web 导出打通。
