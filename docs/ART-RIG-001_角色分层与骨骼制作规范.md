## 0. 先说结论（美术只需要看这一节也能开工）

| 项目 | 结论 |
|---|---|
| 现有角色图能否直接分层？ | **不能。** r02_00 整张是**单一连通体**（4732 px 一块）：马尾在 y=13–21 与后脑连、手臂压在外套上、两腿在 y<118 并在一起。按连通域分离会得到"一整块"。 |
| 本轮分层是怎么做的？ | 按**骨轴几何归属**切分（每个像素归给"距离/半宽"最小的那根骨），不是抠图。可复现、可重跑。 |

| 需要美术补画的面积 | **1551 px，占角色 32.8%**（肩腋 620、髋裆 530、腿部 257、头颈 144）。分部件清单见 §6。 |
| 骨骼方案可行吗？ | **可行。** 18 根骨 / 16 层刚性 Cutout，独立场景已跑通待机与行走，支撑脚世界滑移 0.042 px/帧。 |
| 下一步要美术交什么？ | 见 §8「下一轮交付清单」——一句话：**按 §3 的部件表，交付带完整轮廓的分层 PNG（含被遮挡处补画）**。 |

## 2. 画布与像素参数（不可改）

| 参数 | 值 |
|---|---|
| 画布 | 128 × 176（RGBA） |
| 锚点（节点原点） | (64, 168)，即**脚底** |
| 可见范围 | x 34–99，y 8–167，可见高 **160** |
| 头顶 / 脚底 | y = 8 / y = 167 |
| alpha | 只允许 0 与 255 两档（**禁止半透明羽化**） |
| 纹理过滤 | Nearest（`texture_filter = 1`），1:1，**禁止缩放** |
| 导入参数 | `compress/mode=0`、`mipmaps/generate=false`、`process/fix_alpha_border=false`、`detect_3d/compress_to=0` |

> `fix_alpha_border` 必须为 false：它为 true 时会把边缘颜色渗进透明像素，静止还原度立刻不为 0。

关节是按轮廓实测反推的，不是按人体比例估的：

如果美术的原意相反，只需交换 `rig001_spec.json` 里两组的 `z` 值，骨骼树不用动。

补充说明：
- 这些区域**不是简单"补个色块"就行**：袖根要画出袖子与外套的前后关系，裆部要有裤子褶皱走向，发根要有头发的层次。

## 7. 替换为正式素材的方法（不用改代码）

1. 按 §3 的 16 个图层名，交 16 张 128×176 透明 PNG（`ART_CHAR_001_rig_<layer>_v01.png`），
   每张**只含该部件，且必须画完整**（被遮挡处也要画出来）；
2. 走正常流程登记：`素材库/ID登记表.csv` 查号 → `素材台账.csv` 加行（状态先填"待审核"）→ 拷进 `assets/`；
3. 改 `assets/dev/rig001_proto/rig001_spec.json` 里的 `layer_dir` 与各骨 `origin/tip`（如果关节位置有变），
   **不用重建骨骼树、不用重写动画**；
4. 跑 `--dev-scene=rig001 --rig001-test`：静止还原度应仍为 0 px 差异（同位置同尺寸时），
   支撑脚滑移、封闭孔、比例稳定性会自动复验。

> 如果正式素材调整了关节位置（例如肘从 y=70 挪到 y=68），只改 spec 的 `origin/tip`，
> 步态模型会自动按新的骨长重解 IK。

## 9. 当前技术限制（如实说明）

1. **刚性 Cutout，没有网格变形**：关节处是"两块硬片叠着转"，因此
   肘/膝内侧会有 1–2 px 的台阶（当前实测上体封闭孔 18 px / 8 个相位，单帧最差 3 px）；
2. **像素会随骨骼旋转而"走样"**：本原型所有旋转角都控制在 ±20° 内，
   超过 30° 后最近邻采样会让边缘像素抖动（这是像素风骨骼的固有问题，也是本轮不建议做大幅动作的原因）；
3. **被遮挡区域全是占位色**，只在原型里"不露洞"，不能当作美术结果；
4. **步速与现有移动速度不一致**：骨骼步态设计步速 70 px/s，而 `PlayerController.move_speed = 100 px/s`。
   正式接入前必须二选一（改移动速度 / 改步频 / 改步距），本轮**没有动任何一个数值**；
5. **只有朝右**：朝左仍是水平镜像（与现有 r09 方案一致），没有独立左向分层；
6. 引擎会在 SubViewport 渲染时报 `det == 0`（`affine_invert`）告警，属引擎内部行为，
   不影响输出图像（静止还原度仍是 0 px 差异），已记录在交付报告"已知问题"。
