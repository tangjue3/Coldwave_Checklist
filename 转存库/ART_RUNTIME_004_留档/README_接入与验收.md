本包是独立美术交付件，供外部 Godot Agent 审核与接入，不含游戏代码。**状态：美术候选／待实机验收。**

## 0. 已有工程约束

- Godot 4.7.2，逻辑视口 960×540，最近邻采样，32×32 世界瓦片。
- 购物车正式 ID 已登记为 `ART_FURN_103`；正式运行历史版本 `r01` 是 96×74 可见尺寸的空车。本批基础造型来自先前的加高车把候选 `r02`（96×90 可见），本批分层资产统一记为 **`r03`**。
- 全部 r03 文件使用 **128×112 PNG 画布、脚点/车心定位基准 `(64,104)`，尺寸及位置完全一致**。含 96px 逻辑长度，不改既有碰撞、推拉速度与位置。
- `r02` 是美术候选，**不能认为已由 Agent 接入，也不能直接覆盖 `r01`**。

空载不需要额外的货物贴图：将 Cargo 隐藏即可。

**严格叠放顺序：**

1. `Back` 后景车体
2. `Cargo` 可选（无 / half / full，二选一，不能同时显示）
3. `Player` 当玩家经过篮体或正与车重叠时位于 Back 与 Front 之间
4. `Front` 近侧篮网，镂空处透出货物或角色

所有图层必须以**相同 `(64,104)` 锚点、1:1 scale、整数世界像素位置**叠合。禁止独立缩放或给 Front 添加额外偏移。这是同一辆车的四张图，不是四辆车，也不是四个独立设施 ID。

`Front` 的完整购物篮格网**从同一张 r02 精灵做像素级拆分**，不是 AI 重新画一个尺寸近似但不匹配的篮体。`Back + Front` 重组后与源 r02 空车图 **像素差异数 = 0（ImageMagick AE=0）**。

## 2. 装载状态的美术含义

- 空载：Back + Front。
- 半载：Back + Cargo_half + Front。
- 满载：Back + Cargo_full + Front。

这只是“看起来装了多少”的三档视觉状态，**不负责库存与容量判断**。库存、购物车载重、装载量阈值和超市购物结算仍由后续 `CORE-002` 设计；不允许拿本图替代真实物品数据。

物资图是独立透明 PNG，已经重新整理到原车篮内部，图层尺寸一致，且网格罩在货物前。半载和满载在 960×540 的正常视图里都有可区分的色块与高度，但具体观感仍须实机试用。
