# 《寒潮清单》ART-RUNTIME-001：许知夏运行时精灵首帧

状态：**单帧通过离线图像 QA，等待 Godot 实机验证；不是动画完成版。**

## 1. 本包定位

- `01_runtime_candidates/ART_CHAR_001_r01_idle_right_128x176.png`：**唯一可以被开发 Agent 引入测试场景的 PNG**；方向为朝右、静止。
- `00_source_not_for_runtime/ART_CHAR_001_r01_master_reference_only.png`：高分辨率创作源图，含高分辨率半透明暗影，**严禁直接导入正式游戏**。
- `02_previews/ART_CHAR_001_r01_idle_right_preview_4x.png`：纯供人观看的 4 倍最近邻放大图，背景灰色是预览底色，**严禁作为贴图**。

原 `ART_CHAR_001_v02` 概念设定继续完整保留。本包是相同角色的第一次运行时精灵候选，不得以它替换、删除或改写 v02 的设定资料。

## 2. 已冻结的美术尺度

| 项目 | 数值 | 约束 |
| --- | ---: | --- |
| 游戏逻辑视口 | 960×540px | 整倍数放大，Nearest |
| 世界参考网格 | 32×32px | 不意味着画面底边必是整格 |
| 角色**实际可见高度** | 160px | 5 个 world tile |
| 单帧透明画布 | **128×176px** | 为未来步行动作预留宽度；不能用画布宽当碰撞宽 |
| 本帧可见包围盒 | **41×160px，左上 (43, 8)** | 不含透明边缘；与早期 46px 身宽估算不必完全一致 |
| 建议脚底锚点 | **(64, 168)** | 坐标为纹理左上角起算、向右向下 |
| 碰撞宽度起测值 | 28px | 待实机通道/推车测试，不因贴图画布 128px 改宽 |
| 配色 | 约 89 个 RGBA 颜色（含透明） | 当前单帧试用调色，不是全角色最终调色表 |

之所以使用 128px 帧宽，是因为静止人物虽只有 41px 宽，但侧向步行时前后腿及摆臂会超出 72/80px 静止框。透明画布不参与碰撞。后续动画所有帧应继续共用 128×176、同一锚点，禁止各帧自动裁剪后直接无对齐地混播。

## 3. 现有 PNG 技术检测结果

- RGBA PNG，**128×176**；人物包围盒 **41×160+43+8**。
- Alpha 只有 0 和 255 两档，透明背景真实存在，不是棋盘格烘焙。
- 已去除 AI 生成时产生的黑色晕影，并在 4× 最近邻预览中检查外轮廓。
- 采用较小色表清理高分辨率生成图多余的相近颜色；画面仍按像素原生尺寸核查。
- 当前只是一张静止帧。步行动画试稿存在跨帧服饰/肢体误差，**没有纳入这次正式候选包**。绝不可将其当作完整行走动画。

图像 QA 是必要条件，但不能替代 Godot 中的运行时 QA：门口站位、人物运动、冷暖场景对比、身体与碰撞盒、帧间连贯性必须另测。

## 4. Godot 接入约定

1. 优先在独立开发测试场景加载本 PNG，正式资源归档前先检查 ID 登记表与台账是否有同版本冲突。
2. Godot 像素纹理采用 Nearest，纹理/节点默认 `scale = Vector2.ONE`，不得使用线性插值或小数倍缩放来修补尺寸。
3. 若 `Sprite2D.centered=false`，建议相对于角色**脚底原点**设置节点 `position = Vector2(-64, -168)`；如使用 `AnimatedSprite2D`，所有帧统一锚点，并检查逐帧画面是否漂移。不要把纹理右下角当角色根节点。
4. 现阶段可只挂 `idle_right` 单帧。朝左临时翻转仅供控制测试；正式左右动作仍按美术要求再制作。
5. 角色碰撞宽度从 28px 起测；实际脚底/头部、门净宽和购物车遮挡要按实机截图复核。
6. **未通过运行时测试前**，美术库仍标为「待实机验证 / 运行时候选」，不要标「运行时可用」。

## 5. 开发 Agent 必须交回的证据

- 960×540 **原生 1:1** 截图：灰底轮廓、暖色超市、冷色街道、住宅 96×192 门四个检查点。
- 是否有暗边、锯齿模糊、鞋底悬空、头部被门楣裁切、透明画布误算碰撞宽度。
- Godot 导入日志与实际 PNG 路径、贴图过滤设置、角色节点锚点设置。
- 原有工程与美术库回归测试是否仍通过。
- 对于失败项：给出屏幕截图和具体像素偏差；**不允许悄悄把贴图拉伸或重新绘画替代**。
