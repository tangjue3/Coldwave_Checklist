# 寒潮清单 · 美术设定库（ARTLIB-001）

> 面向**人**查看、讨论、审核的美术资料库；**不是** Godot 运行时资源目录。
> 建立日期：2026-11-08。第一季范围，不涉及第二季。

## 一、最关键的三条规则

1. **本目录与游戏运行时完全隔离。** 根目录的 `.gdignore`（空文件）让 Godot 在文件扫描时整棵跳过。
   **禁止**任何游戏脚本写 `res://素材库/...`，也禁止把本目录的图片当作 `assets/` 的替代品。
   正式运行资源继续放在 `assets/`、`scenes/`，且只能来自审核通过、有批准记录的素材。
2. **概念图 ≠ 可用素材。** 这里允许存在概念图、参考图、角色设定、分镜、动画预览、废弃版本、多版本并存；
   只有台账中 `审核状态 = 运行时可用` 且填了 `对应运行时资源路径` 的条目才允许被游戏引用。
   「已通过设定审核」只说明美术方向定了，**不代表**已经能跑在游戏里。
3. **现有文件只复制、不移动不删除。** 原图继续留在 `assets/reference/` 与 `docs/handover_v1.*/`；
   本库只放一份带 ART_ID 的副本，用于浏览与讨论，避免重复复制产生冗余。

### 编号已正式登记（SCALE-001）

`素材库/ID登记表.csv` 是**编号的唯一来源**，每个号只有三种状态：`已用` / `预留` / `空置`。
可读版 `素材库/ID登记表.md` 由脚本从 CSV 生成，列出号段总览、各前缀的「下一可用号」与完整清单。

**后续生成任何素材之前，必须先查这张表**，禁止重复占用或回填预留 / 空置号。
入库前四步与硬性规则见 `素材库/ID登记表.md` §6；校验命令：

```bash
python tools/check_id_registry.py
```

校验内容：登记表与台账一一对应、预留/空置号没被台账或文件名占用、版本号格式、分类与目录、
文件名与台账一致。任何一项不过，脚本以非 0 退出，不得提交。

## 四、台账状态定义

`素材台账.csv` 里有两个容易混淆的字段，必须分开理解：

| 字段 | 取值 | 含义 |
|---|---|---|
| `审核状态` | `概念草案` / `待审核` / `已通过设定审核` / `正式素材制作中` / `运行时可用` / `已弃用` | 生命周期主状态，决定**能不能进游戏** |
| `制作状态` | `未开始` / `概念绘制` / `像素精修` / `引擎试用` / `已交付` / `不适用` | 产线进度，与审核结果无关 |

`运行时可用` 是**结论，不是标注**。只有同时满足下面三条，才允许写这个状态：

1. `对应运行时资源路径` 非空且指向 `assets/` 内的真实文件；
2. 该路径下的文件**确实存在**（克隆后也在）；
3. 已通过验收并在 `制作与修改说明` 里留下批准人、日期、任务编号。

缺任何一条，条目都必须保持非运行时状态。`tools/check_artlib_page.mjs` 会逐条核对这三项，
并用**白名单**约束「谁可以标运行时可用」：任何新增都必须在脚本里显式加一条，越权即验收失败
（CORE-001B 之前是断言「全库 0 条」，现在改为白名单）。

> 目前白名单三条（都在 `tools/check_artlib_page.mjs` 里写死，新增必须在代码里显式加）：
>
> | 素材 | 状态 | 说明 |
> |---|---|---|
> | `ART_CHAR_001` r01 | 单帧可用 | 朝右静止帧（CORE-001B） |
> | `ART_CHAR_001` r02 | 四帧行走可用 | 朝右行走四帧（ART-INTEGRATE-003） |
> | `ART_FURN_103` r01 | 运行时可用 | 旧购物车，保留为回滚版本（ART-INTEGRATE-003） |
>
> **仍然缺**：转身、搬运、扶车行走循环；朝左仍是临时镜像（由 `PlayerController` 自动做绘制补偿，
> 不碰碰撞盒）。ART-INTEGRATE-003 收进来的 7 个候选件状态是「待总监验收 / 引擎验证通过」，
> 文件已进 `assets/`、已在实机场景里验证，但**没有**标运行时可用。

用户提供的外部参考图一律标注 `版权或授权备注 = 仅作风参考，未确认商用授权`，并且**永远不填** `对应运行时资源路径`。

## 五、从素材库进入正式资源的流程

0. **先查号**：在 `ID登记表.md` 里确认这条内容是「已有条目补版本」还是「新开条目」；
   新开就从对应前缀的「下一可用号」顺延，并在 `ID登记表.csv` 先登记，再动文件。
1. 在预览页 / 台账里选中一个版本，记录 `素材 ID + 版本号`。
2. 由用户或总策划**明确批准**（在 `制作与修改说明` 写批准人、日期、任务编号）。
3. 制作或精修出符合 `docs/开发说明.md` 规格的运行时资源，放进 `assets/` 对应分类。
4. 在台账填入 `对应运行时资源路径`，确认文件存在，把 `审核状态` 改为 `运行时可用`。
5. 之后 Godot 才能引用该文件；`.gdignore` 保证素材库本体永远不会被打进包。

本轮**没有任何素材进入第 2–5 步**，全部图片都还是概念 / 参考状态。

## 六、离线预览页

双击 `素材库/美术总览.html` 即可。数据内嵌在 HTML 里，缩略图在 `.thumbs/`，全部走相对路径，
不需要 Node、Python、本地服务器或网络；`file://` 下也能正常工作。

新增素材或改了台账后，运行一次索引生成脚本重建页面：

```bash
python tools/build_artlib.py
```

脚本会：读取 `素材台账.csv` → 为有图片的行生成缩略图 → 重新生成 `美术总览.html`。
页面支持分类、状态、关键词筛选，点击缩略图放大原图，右侧展示详细说明与相关文件链接；
数据与渲染分离，扩展到数百条也只是多几行 JSON，不需要改页面代码。
