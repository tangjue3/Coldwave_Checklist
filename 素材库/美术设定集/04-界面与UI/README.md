## 命名与版本

沿用全库统一格式，**不另立新规矩**：

```text
ART_UI_<三位序号>_<v|r><两位版本>_<中文短名>.<扩展名>

例：ART_UI_064_v01_仓储面板设计稿.png
    ART_UI_065_r01_仓储底板九宫格.png
```

- `vNN` = 设定 / 概念版本（`v01`、`v02`…），画的是"长什么样"。
- `rNN` = 运行时候选 / 运行时版本（`r01`、`r02`…），画的是"能直接进引擎的那份"。
- 版本号从 `01` 起递增，**旧版本不覆盖、不删除**，台账新增一行并注明与前一版的差异。
- 文件名里的尺寸用 `_宽x高` 结尾（如 `_480x300`）便于对号，和场景素材的习惯一致；只写真实像素，不写"2 倍"这类描述。
- 中文短名控制在 2–8 字，不带空格、括号、斜杠。

**一个 ID 对应一个能独立进引擎的东西**：

- 一整套界面的设计稿 → 领 1 个号（`v01`），图上可以把多个状态并排画在一起。
- 拆成能单独拉伸 / 单独引用的零件（面板、按钮、条、箭头）时，**每个零件单独领号**。
- **图标走图集**：16 枚图标画进一张 atlas 算 **1 个号**，单枚图标不单独领号，靠图集坐标引用。免得为 16 个小图占掉 16 个号。

## 概念图 / 候选素材 / 正式素材（三态别混）

| 阶段 | 版本 | 台账 `审核状态` | 本目录里长什么样 | 能不能进游戏 |
|---|---|---|---|---|
| **概念图** | `v01`… | `概念草案` / `待审核` | 整幅设计稿，可以带背景、可以多方案并排、可以不透明、可以有尺寸标注与文字说明 | **不能**。只用于定方向 |
| **候选素材** | `r01`… | `待审核` / `已通过设定审核` | 已经切好、透明背景、按目标尺寸出图，但没做像素清理 / 没对齐九宫格 / 没验收 | **不能**。`对应运行时资源路径` 必须为空 |
| **正式素材** | `r01`… | `运行时可用` | 与候选同一张（或清理后的一版），已进 `assets/ui/` | **能**。三条同时满足才允许写这个状态 |

`运行时可用` 是结论不是标注，必须同时满足：① 台账 `对应运行时资源路径` 指向 `assets/ui/` 内的真实文件；② 该文件确实存在；③ `制作与修改说明` 里写明批准人、日期、任务编号。缺一条就只能停在候选。

另外两列独立填写：`视觉评价`（认可 / 待优化 / 未评价）、`使用状态`（正式使用 / 回退保留 / 未使用）。三个问题分开答，不用一个标签概括。

## 出图要求

### 画布与分辨率

- 逻辑视口 **960 × 540**，UI **按 1:1 像素设计**。不要按 1920×1080 画再缩小——缩完边框会糊、九宫格边距对不上。
- 只出 1× 图。确实需要 2× 高清版时按**整数倍**另存（文件名加 `_2x`），**禁止 1.5×、1.25×**。
- 所有尺寸取整数像素。半像素位置在 Nearest 下会露出 1px 亮边。

### 透明与颜色

- 一律 **PNG-32 真 alpha**。不要用白底 / 黑底 / 棋盘格截图冒充透明，也不要用"接近黑的深灰"当透明。
- **不要烘焙阴影和外发光**：阴影、描边、发光单独一层出图，或由引擎 `StyleBox` 画。烘焙进去以后换个底色就是一块脏影子。
- 半透明面板要给出底色与 alpha（例如"黑灰 #242B33 @ 78%"），方便程序侧对齐。
- 像素风不允许抗锯齿羽化边。圆角用整像素阶梯，不要用高斯模糊的圆角——Nearest 放大后会变成一圈毛刺。

### 九宫格（面板 / 按钮必填）

- 面板与按钮必须能"四角不拉伸、中间随便拉"，交付时**注明四边切分尺寸**，例如 `九宫格边距：左8 上8 右8 下8`。
- 边距取偶数 4 / 8 / 12，四角图案完整、不与边线粘连。
- 一张图里同时给 `normal / hover / pressed / disabled` 四态时，按状态分行排列，行高固定并写明每行的 y 偏移。

### 导入 Godot 的硬要求

1. 放进 `assets/ui/` 对应子目录，文件名用**小写英文 + 下划线**，不要中文名——`assets/` 是运行时目录，命名规则与本资料库不同。
2. `.import` 必须：`process/fix_alpha_border=false`、`detect_3d/compress_to=0`、无损（`compress/mode=0`）、`filter=Nearest`。
3. 九宫格用 `NinePatchRect` 或 `StyleBoxTexture` 的 `texture_margin_*`，不要用 `scale` 硬拉。
4. 图标图集在 `AtlasTexture` 里切分，切片坐标写进台账或同目录说明，别只留在某个人脑子里。
5. 尺寸核对：把图拖进 960×540 的场景，`scale=1` 时应与设计稿标注的像素完全一致。

## 素材 ID、台账与审核流程

沿用 `素材库/README.md` §五 与 `ID登记表.md` §6，这里只写 UI 特有的部分：

1. **先查号**。在 `素材库/ID登记表.md` 里搜内容，确认是"已有条目补版本"还是"新开条目"。
2. **定号**。新开一律用「下一可用号」（当前 `ART_UI_064`），**不得回填空置位、不得占用预留位**。
   `ART_UI_001 / 002 / 003` 是 v1.1 的规划预留位（HUD 与购物车 / 建造模式 / 对话框）；只有在**对应资产真正入库**时，才由美术总监裁定改成「已用」，其余一律从 004 往后排。
3. **登记**。先在 `素材库/ID登记表.csv` 加一行（状态 `已用`），再动文件与台账。
4. **入台账**。`素材库/素材台账.csv` 加一行：`所属分类=界面`、`库内文件路径=美术设定集/04-界面与UI/<子目录>/<文件名>`、版本、尺寸、审核状态。
5. **校验**。跑两条，全绿才提交：

```bash
python tools/check_id_registry.py     # ID ↔ 台账 ↔ 文件名 ↔ 目录 一致
python tools/audit_artlib.py          # 台账 ↔ 磁盘 ↔ assets/ ↔ 死链 交叉审计
```

> ⚠️ **本目录不接受"先扔进来再说"的图片。** `audit_artlib.py` 会把 `美术设定集/` 下任何未登记的图片判为失败（`.md` 除外）。要么登记台账，要么先放 `06-待审核/`——那里同样需要登记。
> 只放说明文件（`.md`）不会报错，所以各子目录默认放一份 `README.md` 占位。

6. **进引擎**。按 `素材库/README.md` §五 第 3–5 步：精修 → 放 `assets/ui/` → 台账填运行时路径 → 改 `运行时可用` → 在 `tools/check_artlib_page.mjs` 的 `APPROVED_RUNTIME` 白名单里显式加一行（不加就是越权，验收会拦下）。
7. **重建预览页**：`python tools/build_artlib.py`。

## 和运行时 UI 的关系

- 本目录是**资料库**，根目录 `.gdignore` 让 Godot 整棵跳过；**禁止**任何脚本写 `res://素材库/...`。
- 运行时 UI 只认 `assets/ui/`。那里现在有：`fonts/`（思源宋体 400/600/900、霞鹜文楷 Screen、旧思源黑体）、`fonts/variations/`（字重实例）、`labelsettings/`（13 个文字样式预设）、`themes/main_theme.tres`（现役全局主题）、`themes/font_theme.tres`（字体主题，仅在预览场景用）与 `menu/`（主菜单背景，目前唯一一张 UI 贴图）。
- 文字样式的扩展走 `assets/ui/labelsettings/` 与 `assets/ui/fonts/variations/`，规则写在两处的 README 里，**不在本资料库做**。
- 主题的扩展（新控件样式）改 `assets/ui/themes/main_theme.tres` 与生成脚本 `scripts/dev/generate_ui_theme.gd`。
- 概念图再漂亮也不等于可用素材：一张 HUD 设计稿要变成游戏里能跑的东西，还得过九宫格切分、四态、透明清理、尺寸对齐、`StyleBox` 配置与实机验证。
