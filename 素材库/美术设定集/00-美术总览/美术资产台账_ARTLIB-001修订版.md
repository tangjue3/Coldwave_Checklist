# 《寒潮清单》美术总监手册与素材生产台账 v1.1

> 当前状态：**规划与概念阶段**。本表是今后我负责生成、审核和交付素材的总清单，非“所有资源已经做好”。正式游戏资产须满足统一像素密度、透明背景、帧对齐、碰撞与运行测试，图片生成的气氛图不能直接充当动画帧。

## 1. 项目统一视觉规格

**固定风格描述**：2D 正侧视、偏写实的正常人物比例、精细手工像素、清晰的深色像素轮廓、受控且低饱和的灰棕/暗绿/烟蓝配色；大面积柔和但不模糊的像素块阴影；灰暗末日街道与暖黄安全屋形成强烈对照；精致成熟的独立像素游戏，不是 Q 版、8-bit 大块色、3D 渲染或高清二次元立绘。

**主角原创设定（提案，等待用户审美确认）**：许知夏，24 岁，普通身材，清爽短碎发/低扎头发可二选一；墨绿色防风工装外套、焦褐色围巾、深灰工装裤、旧米色帆布鞋、小斜挎包。剪影要与用户风格参考图明显不同，保留正常比例和细腻像素笔触即可。待定稿前不生产大批动作帧。

**色板初稿**（实际由首个场景和人物试稿校准）：

| 用途 | 色值 | 用法 |
|---|---|---|
| 最深轮廓 | `#2B292E` | 人物、货架、家具主要边线 |
| 炭灰 | `#474148` | 衣服阴影、墙体 |
| 烟棕 | `#6B5E57` | 地板、箱子、旧木家具 |
| 旧绿 | `#536157` | 工装、设备、部分 UI 强调 |
| 纸张米白 | `#D3C6B2` | 清单、说明、图标留白 |
| 风雪蓝灰 | `#718091` | 室外冷调、玻璃霜 |
| 暖光橘金 | `#D3A46C` | 安全屋灯光、热食、炉火 |
| 危险铁锈红 | `#A76250` | 危险提示、门板、低温警示 |

**尺寸基线**：目标内部视口 `960×540`；暂定世界 tile `32×32`；主角 spritesheet 单帧试稿约 `96×192` px，实际像素绘制统一缩放；主要 UI 图标建议 24/32/48 px 几档；最终统一后不可随意将高清素材缩到不同像素密度。Godot 中世界精灵使用 nearest filtering + 整倍数缩放。

**界面**：黑灰半透明面板 + 米白清单纸纹理 + 暖黄数值提示；中文字体确保读得清楚，不要因为像素感强行使用难辨的破碎字形。人物气泡短句在人物身边，重要对话进入底部对话栏。

## 2. 素材命名与交付验收

**目录命名建议**：

```text
assets/
  characters/hero/hero_idle.png
  characters/hero/hero_walk.png
  characters/hero/hero_shop.png
  characters/npc/chen_idle.png
  scenes/supermarket/supermarket_bg.png
  scenes/shelter/shelter_base.png
  tiles/indoors/house_tileset.png
  items/icons/food_box.png
  items/stacks/food_box_stack_01.png
  facilities/heater/heater_off.png
  facilities/heater/heater_on.png
  ui/icons/icon_temperature.png
  ui/dialogue/dialogue_frame.png
  effects/weather/snow_loop.png
```

**每批验收**：文件尺寸和透明背景一致；没有水印/乱字/不规则多余手指；人物四肢与头部比例稳定；坐标与 pivot 一致；动作没有角色忽胖忽瘦；商店和房间道具可实际碰撞/点击；不同 NPC 不共享同一张脸；神态清楚但不夸张；全部素材归属与授权可追溯。

## 5. 资产生成先后与成本控制

### 批次 A：锁定人物与相机（当前阶段可做）

1. 主角 1 套原创人物概念卡：标准侧面+正面+背面+局部五官，像素密度一致。
2. 超市和初始小楼各 1 张 2D 横版构图图；对照角色比例与世界 tile。
3. 道具/家具像素密度样本：瓶水、纸箱、金属货架、暖器、发电机。

**输出是视觉定稿参考；**不把这些独立概念图声称为能直接导入动画系统的资产。

### 批次 B：最小可玩正式图（工程验证后）

1. 主角四组独立动作 sprite sheet；导入 Godot 实际看是否跳帧、闪烁、体型变化。
2. 一套超市 tile + 安全屋 tile，配可交互货架、可放置家具。
3. 8 商品图标、4 类堆叠图、HUD 和对话框。

**交付标准**：至少存在一条真实 2D 横向行走、购买、回家摆放并亮灯的可运行流程。若自动生成的 sprite sheet 不规则，需要人工像素清理或重新生成；不能仅为赶进度将大图切片硬塞。

### 批次 C：完整第一季

待 MVP 测试后，按剧情触发顺序补齐 NPC、场景、节奏性插画和结局屏。每次仅允许加入一个小批次并做游戏内截图对比，防止风格逐渐漂移。

## 6. 统一生成与精修提示词规范

**统一正向视觉描述**（给图像生成作为方向参考，不是自动产出像素精灵的保证）：

> Original 2D side-view pixel art indie survival game; normal adult human proportions; handcrafted crisp pixel clusters with controlled dithering, deep charcoal outlines, muted smoky brown and dark olive palette, cold blue-gray snowfall exterior contrasted with warm amber lamplight inside, worn practical materials, subdued mature Japanese-inspired pixel illustration, consistent fixed pixel density, orthographic side profile gameplay composition, no perspective distortion, readable interactive silhouettes.

**统一禁止项**：

> No 3D, no isometric view, no photorealism, no chibi proportions, no glossy vector shapes, no mobile-casual gradients, no cinematic depth of field, no text/watermark, no copied character design, no mixed pixel resolutions, no blurred antialiasing, no excessive tiny details that hide clickable objects.

**动作 sprite sheet 特殊要求**：画面必须透明背景、每帧同一像素画布、同一脚底基准线、角色颜色/服装/面部一致、边界不裁切。图像模型生成不保证这些条件，必须经过严格导入和 QA；若不满足，先按姿态制作关键帧，后由像素清理流程完成循环。

## 7. 项目协作台账字段

每张正式素材应记录：

```text
asset_id | 文件路径 | 用途/关卡 | 源风格卡版本 | 源生成图/草图 | 是否透明 | 像素尺寸 | 帧数 | pivot | 审核状态 | 是否已导入 | 授权状态 | 备注
```

审核状态仅使用 `待生成 → 概念待审 → 像素精修 → 引擎试用 → 已验收`。**生成图片 ≠ 游戏资产已验收**。

## 8. 角色与资产版权边界

- 用户提供的“周禾”参考角色图片只用于画风学习和私人企划，不认定其角色造型可复制、修改或商用。
- 主角“许知夏”须独立设计可识别的发型、配色、服装和随身物件。
- 任何参考现有游戏截图或短剧海报的构图只可用来分析通用机制/视觉语言；禁止抠图、复用标志和原台词。
- 发布前需要对字体、背景、音效、插画和 AI 生成素材的合法使用条件做最终检查。
