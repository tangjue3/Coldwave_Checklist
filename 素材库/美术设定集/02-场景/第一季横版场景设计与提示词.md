# 《寒潮清单》第一季横版场景设计与提示词

本文件用于第一季场景构思、生成参考图和后续切片规划，配合[第一季完整剧本](../07-世界观与剧情/第一季/第一季完整剧本.md)阅读。所有地图长度、分段和室内布局都是**待画面与操作验证的方案**；提示词生成的是概念图，不是现成的 Godot 地图或正式素材。

## 1. 第一季横版空间关系

第一季以一条**从左向右延伸的长街**组织空间：左侧是主角住处，向右依次经过社区、商店和仓库。玩家在同一条横向行走线上左右移动，镜头跟随；沿街的门是进入室内的交互入口，不代表玩家要在地图里向上、向下或向纵深走。

### 1.1 室外主地图：从家向右走

下面是地图上的**实际排列顺序**。方框是沿街可辨认的地点或地标，横线是连续地面；位置和间距供画面与白盒设计，不是最终工程坐标。

```text
画面左侧 / 家                                                       画面右侧 / 城市边缘

  小楼设备区 ─ 正门巷口 ─ 公告栏 ─ 居民楼单元门 ─ 维修角 ─ 物业门岗 ─ 公交站
       ─ 便利店 ─ 药店门口 ─ 超市入口 ─ 五金家电店 ─ 临时管制路口 ─ 批发仓 ─ 物流中转口

        玩家沿同一条地面线 ← 向左 / 向右 → 行走；到各建筑门前交互进入内景
```

例如：从家门向右，先经过公告栏、居民楼单元门、物业门岗和公交站，再到便利店、药店、超市、五金店；继续向右经过管制路口才是批发仓和物流中转口。回家时沿同一条路向左返回。居民楼与主角小楼隔着巷道，是不同建筑；横版画面把可互动入口沿同一条行走线展开，不要求画出可向纵深穿行的道路。

长街可按制作和性能需要拆成三段，但相邻段必须首尾相接，切换前后的地面高度、建筑顺序和方向保持一致：

| 从左到右 | 室外段落 | 段内顺序 | 主要用途 |
|---|---|---|---|
| 第一段 | **家门—梧桐里社区** | 小楼设备区 → 小楼正门与巷口 → 公告栏 → 居民楼单元门 → 维修角 → 物业门岗 → 公交站 | 重生、收货、邻居对话、门口求助、清雪 |
| 第二段 | **街角—商业街** | 公交站之后 → 便利店 → 药店门口 → 超市入口 → 五金 / 家电店 → 临时管制路口 | 日常采购、唐宁事件、价格变化、道路变化 |
| 第三段 | **批发仓—中转点** | 管制路口之后 → 批发仓入口及装卸区 → 物流中转口 → 地图右侧边界 | 大宗采购、订单取货和运输剧情 |

这三段共同构成一条很长的横版路线，不是三条彼此平行的街。段落之间可以无缝拼接，也可以在相邻边界短暂加载；无论采用哪种方式，玩家从第一段**右边**离开，必须从第二段**左边**进入，返回时反向对应。每段可先按约 4,800–6,400 px 做白盒起点，全程约 14,400–19,200 px；实际长度要按移动速度、镜头和体验调整，不能当作已定稿的尺寸。

### 1.2 沿街门与室内横版地图

室外主路保持一条左右走道。玩家走到对应门口并交互后，进入另一张同样**从左到右**展开的室内地图；从室内出口离开时，回到刚才进入的那扇室外门旁。

| 室外入口，从左到右 | 交互后进入 | 室内从左到右的建议顺序 | 返回位置 |
|---|---|---|---|
| 小楼正门 | 主角安全屋一层 | 卧床 / 外婆照片 → 清单桌 → 储物区 → 厨房 → 玄关与门 | 小楼正门巷口 |
| 居民楼单元门 | 居民楼公共楼道 | 楼梯口 → 楼道窗 → 住户门 → 另一端边界 | 同一单元门外 |
| 便利店门 | 唐宁的便利店 | 货架与冷柜 → 收银柜台 → 后方门 | 便利店门外 |
| 药店门 | 药店内景，扩展建议 | 入口 → 等候位 → 非处方陈列 → 药师柜台 | 药店门外；现有剧本只提到药店，不要求玩家进入 |
| 超市入口 | 超市内景 | 入口 / 推车 → 饮水与食品 → 后仓预约位 → 冷柜 → 收银与出口 | 超市入口外；若另设室外出口，必须在白盒中明确对应位置 |
| 五金店门 | 五金 / 家电店 | 入口 → 工具墙 → 门窗密封 → 取暖 / 发电设备 → 收银与装货口 | 五金店门外 |
| 批发仓入口 | 批发仓和装卸区 | 入口 → 托盘和货架 → 订单交接 → 装卸门 | 批发仓入口外；装卸门若连到室外，须明确另一个对应位置 |
| 物流中转口 | 中转点取货区 | 入口 → 等候区 → 中转棚 → 交接窗口 | 物流中转口外 |

赵阿姨家从**居民楼内的住户门**进入；陈叔维修角可从社区段的维修门进入或只在外部显示。屋顶小狗、天线、电台特写和前世回忆都是对应建筑的局部画面，不另接在街道最右端。是否开放这些室内入口，由后续具体任务决定。

小楼二层位于一层上方，是**同一栋建筑的楼层关系**，不另画到长街左端或右端；玩家从屋内楼梯到二层，镜头可向上移动或切换楼层。小楼设备区在室外主路最左侧，与生活空间隔离并通风，可通过独立门进入；窗外风雪只是背景层，不是另一条可走路线。P00 的前世门外走廊与居民楼公共楼道属于不同地点，可以复用墙体素材，但不能混成同一扇门。

### 1.3 场景制作与剧情状态

- **灾前**：玩家从家出发，沿长街走向对应商店；独立批发仓在 D-4 后开放，D-6 的临时批发预约仍在超市内。
- **灾后**：保留同一长街的地点顺序与门口位置，通过积雪、灯光、卷帘和风雪图层表现变化；商店是否开放、远端是否可达由剧情决定。
- **事件位置**：收货和孟雨薇敲门发生在小楼正门；赵阿姨、小满及物业活动主要在居民楼与门岗一带；唐宁的对话和交易发生在便利店或其门口。
- **边界与通行**：门前、街道和相邻地图接缝均保留行走及交互空间。箱子和雪可以暂时形成剧情障碍，但必须提供整理、清理或合理绕过的方式，不能永久堵死关键路线。

以上是第一季场景**规划**，不表示这条地图或室内转场已经在游戏中实现。

## 2. 横版地图共同规格

| 项目 | 场景设计起点 |
|---|---|
| 视角 | 2D 正侧视；室内建筑采用正面剖开墙体的横版视图。保持统一机位、水平地面和垂直墙体，不使用俯视或 45° 等距。 |
| 视口与角色 | Godot 逻辑视口 **960×540**；角色可见高约 **160 px**、宽约 **41 px**，世界基准格 **32×32 px**。角色动画当前使用高分辨率帧缩小显示，不能据此把地图重新定成另一套尺度。 |
| 门和道具 | 住宅门约 **96×192 px**，超市入口约 **192×224 px**，四层货架约 **96×192 px**，购物车逻辑侧视长约 **96 px**。以角色脚底和统一地面线对齐，预留交互与碰撞边界。 |
| 地图长度 | 以下长度为初稿，不是已冻结工程尺寸：小空间约 1,920–2,880 px，街道/商店/社区约 3,840–6,400 px；即约 2–7 个 960 px 视口。通过门、转角、背景重复模块和可识别地标组织长地图。 |
| 高度 | 地面探索区优先单一行走线。安全屋两层应先按角色高度、门高、楼板厚度与镜头可视范围做白盒验证；可用镜头上下移动或缩放呈现，不承诺两层一定同时完整塞进 540 px。 |
| 图层 | 远景天空/建筑 → 中景建筑立面和墙 → 场景固定背景 → 可交互对象与人物 → 必要的前景遮挡 → 雪、风、雾与灯光 → UI。商品、门、物资和设备需要独立层或节点。 |
| 地面与通路 | 单张背景上不画人物脚印来替代真实移动。地面连续；对话站位、推车和货箱旁留足宽度；门口不得因物资堆放永久封死。具体碰撞与通道尺寸由白盒测试确定。 |
| 天气与状态 | 灾前、初雪、暴雪、风暴后尽量使用同一地图坐标与碰撞，叠加积雪、风雪、灯光和店铺开闭状态。安全屋升级通过独立设施、家具和库存组合表现。 |
| 格式 | 正式切片遵循工程当前的导入与透明度规范；概念参考可以有光影与柔和边缘，但不能直接作为地图图块、交互物或已验收运行资源。 |

**长图生成与拼接**：先生成整条街/室内的低细节概念草图，明确地标顺序和共同地平线；再按固定镜头和等比例制作 960 px 左右的分段草图，相邻段额外保留约 10%–20% 重叠供人工对齐。提示词要求连续的墙、地板、照明和重复模块；人物、可移动货物、标牌文字不烘焙进背景。此重叠只是概念对接建议，最终分辨率、接缝和切片尺寸需实测。不要靠拉伸一张小图制造长地图。

**系统提示与场景的关系**：寒潮生存系统是只有女主和玩家能看到的游戏 UI，任务、进度和待领取奖励由屏幕空间控件显示；它不是世界里的固定广告牌或悬浮实体，不烘焙进任何场景背景。系统奖励可通过背包或已有的领取界面表现，领取后才显示实际物资；无需在所有地图制作“宝箱掉落点”。奖励和任务仍属于策划，界面与机制尚未实现。

## 3. 所有场景共用的画风提示

**正向基础词**：

> 原创 2D 横版生存经营游戏场景，正侧视、固定水平镜头、连续向左右延伸的地图，手工制作感的精细像素美术，正常人物比例的场景尺度，低饱和烟蓝灰、旧绿、灰棕与米白，清晰结构轮廓和可识别材质，末日前的旧城区生活感，冷色风雪与室内暖黄灯光对比，地面连续，门和互动位置留白，无人物和 UI，游戏背景分层设计，适合拆分为可重复拼接的环境模块。

**共同排除词**：

> 俯视、鸟瞰、45 度等距、斜向透视道路、3D 建模、照片写实、Q 版、巨头人物、人物烘焙在背景里、活动商品和文字烘焙在墙上、关卡走道被杂物封死、极度倾斜地平线、透明伪网格、水印、可辨识品牌和现成游戏角色、错误中文招牌、硬拼贴断墙、同一场景不同分段的门窗位移。

文字招牌建议先留空白牌面，后续用独立文字覆盖；图片模型容易生成错字。所有提示词为视觉方向，尺度和交互由白盒、切片和运行验证决定。

## 5. 逐场景构图与提示词

以下提示词均可在前面追加“共用正向基础词”，并搭配共同排除词。方向以玩家镜头画面从左至右为准；出入口具体朝向可以在白盒阶段调整，但相互连接后应保持一致。

### A. 外婆旧小楼一层 / 安全屋主体

**剧情与用途**：重生醒来、发现清单、入库、检查门锁、做饭、与门外人物对话、结局。玩家多次返回，空间必须能从破旧但可居住，逐渐被真实购入的设备和物资填充。

**建议横向分段**：左侧卧床和外婆照片 → 小桌与纸质清单、绿植 → 储物墙和可摆放货架 → 厨房或简易生活区 → 玄关和临街门；楼梯接二层。建议 3–4 个视口宽，连续楼板与墙面，转场门、货架和玩家行动线分别留位。已选概念不强制上述左右顺序，制作时先锁定一套并贯穿所有状态。

**状态**：初始态墙面老旧、少量基本家具与有限库存；建设中增加已安装设施、已付款物资、修补痕迹；寒潮中按实际供电显示亮灯或暗屋、霜窗和雪影。升级态保留门、窗、楼梯与建筑轮廓位置，设施和库存不应整张换图冒充。

**提示词**：

**状态与演出**：灾前陈叔可在工作台整理老化线缆；停电后用手电检查工具；D03 是否出现修理服务和消耗材料仍由 `chen_helped` 与库存决定。新增一句可选对白：“工具能修东西，备件没了也得想办法找。”

**提示词**：
> 旧居民楼旁的小型维修角，正侧视横版游戏空间，半开旧卷帘、工具墙、磨损工作台、空白零件抽屉和一张旧椅，电工工具只作独立道具陈列，地面留有清楚行走与交流空间；灾前正常照明，停电后可切换手电光和关门状态，不把修理后的设备或零件奖励画死在背景里。

### R. 门岗临时信息 / 交换点

**剧情依据与定位**：D01B 的信息登记、D03B 的交易消息、D04 清路、D07 点名均已有；把门岗旁一段作为可见的信息与交接位置是**新增场景组织**。唐宁的交易商品仍以实际库存与既有交易入口为准。

**横向位置与分段**：社区主公告栏 → 居民楼门 → 维修角 → 物业门岗窗口 / 小纸条夹 → 可选交接桌 → 公交站。交接桌、纸条、灯和库存单独分层；主公告栏始终在居民楼门的左侧，门岗的小纸条夹是另一处信息位。此处可直接复用 F 的门岗和公告栏。

**状态与演出**：D-7 为普通公告；D+1 出现求助和住户联系信息；D+3 后视任务开放真实交易交接；D+7 显示点名记录。玩家拒绝帮助也能查看公开消息；不把所有居民或物资固定画进场景。

**提示词**：
> 梧桐里居民楼与公交站之间的物业门岗，正侧视横版街道局部，岗亭小窗、可单独替换的纸条夹、靠边折叠交接桌和继续向左右延伸的通道；社区主公告栏仍位于居民楼入口左侧。天气从平常逐渐变为积雪，纸条、桌面物品、灯光和人物完全独立；既有社区生活感又能容纳多轮灾前灾后剧情，不出现可读乱码或虚构满桌物资。

### S. 超市预约区与后仓门

**剧情依据与定位**：P02B 超市临时批发预约和物流交接已存在。这里明确它是 H 超市内部一段，和 D-4 才开放的独立批发仓 K 不是同一个地点。

**横向位置与分段**：接在超市食品区与冷柜之间：货架末端 → 临时预约桌 → 后仓门 → 可更换的待交接托盘 → 冷柜。后仓门可只做背景门，不要求玩家进入完整后仓。

**状态与演出**：D-6 可见预约窗口；玩家选择支付运费、分两趟或不追加采购时，用提示与实际订单表达后果；D-3 后窗口关闭或撤桌，不能让未付款的箱子直接回家。

**提示词**：
> 与同一超市横版地板、灯带和货架对齐的临时批发预约区，食品货架末端、可移动登记桌、空白提示牌、后仓门和预留的托盘位置，左侧接货架右侧接冷柜，购物车可以从前方经过；订单纸、箱子和工作人员均为独立层，提供开设预约、关停和空托盘状态，不生成店外独立仓库。

### T. 遮棚屋顶、小狗与天线观察位

**剧情依据与定位**：S04 已有屋顶小狗，D06 有天线相关情节。小狗位于邻居建筑的遮棚屋顶；天线属于可联系电台的相关位置，两者可以共享屋顶素材，**不是同一地点或同一互动**。

**横向位置与分段**：主街居民楼或窗外可见低遮棚，顶部从左到右为屋沿 → 小狗可站立位置 → 排水管与积雪 → 邻楼轮廓。主角默认从地面或窗边观察；天线用安全可达的既有位置或局部镜头表现，不强行加入屋顶跳跃地图。

**状态与演出**：S04 只在 D+2 至 D+5 按条件出现犬吠；玩家可给食物或请邻居寻找主人，食物实际消耗按剧本。没有触发 S04 时屋顶为空；D06 天线修复不自动带来小狗或奖励。

**提示词**：
> 旧城区居民楼窗外可见的一段遮棚屋顶，横版正侧视，屋沿、排水管、可替换积雪、邻楼轮廓和清晰的屋檐层次；为独立小狗精灵留出落脚位置但背景不画小狗，风雪与天空分层。另提供属于相应建筑的电台天线局部特写，固定结构不变，不描绘玩家在暴雪中进行危险攀爬。

### U. 临时管制路口与封雪路段

**剧情依据与定位**：P02B 提到道路管制、P07B 订单延误，D0 交通停运；具体管制路口是新增视觉设计。它位于五金店与批发仓之间的横向主街，不增加必须通过的战斗或清障关卡。

**横向位置与分段**：五金店外 → 空白路牌 → 活动护栏和道路公告 → 路边停靠位 → 批发仓方向。护栏和雪为独立层，是否允许继续前进由当前剧情决定。

**状态与演出**：D-7 至 D-3 普通通行；D-1 出现交通提示但不能把玩家还需前往的订单地点无条件封死；灾后可关闭远端并解释原因。若 P07B 自取订单有效，必须有可达路径；如果无法自取，应在玩家选择前明确禁用原因并保留其他合法选项。

**提示词**：
> 旧城区商业街通往仓储区的横版正侧视道路节点，五金店末端、空白路牌、可移动护栏、临时公告牌、路边停靠位和向右继续延伸的同一地面线；灾前通行，寒潮前出现可替换管制设施，灾后积雪加深。护栏和雪单独分层，保留可以打开的路径，不画透视高速公路或固定交通事故。

### V. 手机、清单、电台与系统提示

**剧情依据与定位**：采购清单、群消息、天气广播、系统任务与领奖在剧本中贯穿全季。它们是独立的界面或道具特写，**不是一条新的横向可探索地图**。

**画面拆分**：A 内小桌上放可交互纸质清单或电台；手机消息、任务进度与待领取奖励显示在屏幕 UI；D06 修理后才显示电台正常工作。建议为纸面、手机壳、电台本体分别设计图形，具体文字由游戏排版。

**状态与演出**：P00 系统绑定；P01 起展示任务和奖励；D01 市电中断；D06 根据真实设备与 `radio_repaired` 展示相应播报；D07 显示真实清单和结局统计。未领取的奖励只出现在待领取列表，不能在场景货架中提前出现。

**提示词**：
> 横版末世生存游戏的独立道具与 UI 概念：磨旧的纸质清单、简洁手机边框、旧式收音机外壳、克制的半透明任务提示框，低饱和米白、烟灰与暖黄色，适合清楚叠加可排版中文；每件物品独立展示，界面文字留空，不把系统窗口、奖励或人物烘焙进房间背景。

### W. 孟雨薇住处外观：她也有自己的门

**剧情依据与定位**：已有孟雨薇灾前离开、灾后求助的情节，但剧本未写她家所在位置或室内活动。本条为**新增可选场景建议**：在居民楼旁使用一处普通门窗表现，不设她必定居住在赵阿姨家，也不要求玩家进屋。

**横向位置与分段**：在公告栏与居民楼单元门之间，或作为单元楼另一扇明确门牌的住户门；画面按左到右接回现有社区路线。若最终认定她住在居民楼里，则仅在 G 楼道放置独立门牌，不同时出现第二套自住房屋。

**状态与演出**：D-1 她可以从该入口离开或仅通过消息提及；D+2 主要仍在主角家门口求助。灾后通过窗光、门前积雪或短信暗示她的处境，不无条件呈现饥饿死亡，也不替玩家决定是否援助。

**提示词**：
> 同一旧城区住宅街的一处普通住户门窗，横版正侧视，与相邻居民楼墙面、地线和窗户尺度统一，入口留出人物经过与对话空位；灾前平常，寒潮后通过可替换积雪、灯光和门窗状态表现，无固定人物、无夸张豪宅或独立剧情结论。

## 7. 从概念到可玩地图的交付顺序

1. **先统一地标**：画一张空间关系草图和 E 的长街白盒，确定小楼、居民楼、门岗、商业街的顺序和出入口；抽样检查 160 px 角色、门和购物车比例。
2. **先做核心地图**：A/D 小楼与门前、E/F 社区街道、H 超市，使用可交互的独立门、货架和物资占位测试移动、遮挡与推车。
3. **扩展**：补 I 五金店、J 便利店、B 二层、C 设备区，再复用模块制作 K/L 和 G 的两处走廊。优先从长街或既有地图切出 O 公交站、R 门岗点、S 超市预约区、U 路口与 V 特写；N/P/Q/T/W 的额外内景或局部画面按剧情需求逐项制作。
4. **统一天气与状态**：在相同世界坐标下制作雪层、窗霜、灯光、店铺开闭，核对玩家视线、碰撞和门口通行。
5. **交付检查**：至少检查一个全长滚动预览、各相邻片接缝、角色站位和交互距离、推车通行、分层透明、空/少/满库存以及安全屋升级前后门窗坐标；具体尺寸以验证结果更新。

本文件只描述场景与提示词，未生成场景图、正式切片、游戏地图或可玩的剧情系统。
